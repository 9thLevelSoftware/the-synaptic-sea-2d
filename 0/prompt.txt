  - Options:
    - `const` of plain literal rows (arrays/dicts of ints and strings), converted to `FieldSpec` by a `static func fields() -> Array[FieldSpec]` or by the loader.

  B2. Packed-array exposure breaks the immutability guarantee (section 1.5, "packed arrays exposed as a copy built once") [high, ~85%].
  - In GDScript, packed arrays returned by script-defined getters are shared references, not copy-on-write values. The engine docs say packed arrays are always passed by reference, and only built-in properties/methods return copies.
  - A getter that returns a "copy built once" hands every caller the same mutable object. One caller's write corrupts what every later caller sees. This undermines AC-85.
  - `make_read_only` does not exist on packed arrays.
  - Pick one:
    - Typed `Array[int]` plus `make_read_only()`. This is safe and allocation-free per call; the cost is boxed Variants.
    - Index accessors such as `count()` and `at(i)`, exposing no container.
    - `duplicate()` per call, which allocates and violates AC-69.
  - Closely related: GDScript has no private fields, so `_field` on a row object is only a convention. The "write-once" claim is enforced by lint and test, not the language. Say so.
  
  B3. The AC-69 zero-allocation test cannot detect the failure it targets (Validation Criteria, `Performance.get_monitor(Performance.OBJECT_COUNT)`) [high].
  - OBJECT_COUNT counts only `Object` instances (Node, RefCounted, Resource).
  - Arrays, Dictionaries, Strings and packed arrays are Variants, not Objects, so a query that returns a fresh `duplicate()`d array leaves the delta at zero.
  - The monitor is valid for "no new Objects" and for the "exactly 25 Objects" load check. That load check needs the loader and all temporaries (JSON, FileAccess, ContentRead, BootError, IntRead, FieldSpec) out of scope first.
