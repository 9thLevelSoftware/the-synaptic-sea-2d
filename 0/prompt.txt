  Second opinion on ADR-0001/0002/0003 (Godot 4.7.2). I read the three ADR sections and the engine reference docs, and changed no files. None of this was run in an editor. Where I rely on engine-source memory I say so.
  
  **(1) Audit findings**
  - Confirmed: all three ADRs have Engine Compatibility sections and pin 4.7.2. The OS.get_ticks_* and device==0 mentions are prohibitions. The 0002/0003 interface text agrees.
  - Challenged: "no deprecated or invalid API" is too strong, because the audit only checked the deprecated list. See H1 and L2 below.
  
  **HIGH**
  - **H1. ADR-0002, Engine Compatibility (1) and Decision §3 step 2 (also §9).** `var_to_bytes(payload, false)` is the Godot 3 `var2bytes(var, full_objects)` shape. In Godot 4, `var_to_bytes(variable)` takes one argument. The object-encoding variants are `var_to_bytes_with_objects` and `bytes_to_var_with_objects`. As written it should be a parse error ("too many arguments"). Use `var_to_bytes(payload).size()` and plain `bytes_to_var`. I am highly confident of this. A one-line parse check would settle it.
  - **H2. ADR-0003, Verification (3), marked UNVERIFIED: "a Callable bound to a RefCounted method keeps the object alive". I believe this is false.** A method Callable stores only the ObjectID, not a reference. A GDScript lambda that captures `self` does hold a reference, which is the leak ADR-0002 §1 describes. If an owner is freed, `is_valid()` goes false and the callable is dead.
    - The composition root must therefore hold every owner in an explicit strong-reference array.
    - The teardown rule and the `Performance.OBJECT_COUNT` test should be re-derived from "callables do not own".
  
  **MEDIUM**
  - **M1. ADR-0003 §3 (token check) and Verification (1).** The design assumes a runtime error aborts the owner callable, so the return value is not the token. In release templates, many GDScript VM checks are compiled under `DEBUG_ENABLED`. I believe a release build can print an error and keep running, then reach `return ctx.complete()`. This is from memory of the source and is not confirmed.
    - Spike KRN-CTX-06 should test both "aborts" and "continues after the error" on a release export.
    - Fail-closed must not depend on the abort. The `WriteScope` closing and the `STRICT_DEBUG` checks have to carry it.
  - **M2. ADR-0003 Implementation Guidelines.** Nothing bans `await` inside owner callables or handlers.
    - A suspended callable returns a coroutine state object, not the token. That is caught as INCOMPLETE.
    - The coroutine later resumes against a context and scope that have since been re-armed, and it can write through them.
    - Add a lint banning `await` in `src/sim/` callables.
    - The kernel should hold the call result as `Variant` and compare it with `is_same()`. A typed `var t: CompletionToken = REDACTED would itself error on a wrong type.
  - **M3. ADR-0001 §2 (boot-time tree walk).** `process_thread_group` defaults to INHERIT, not MAIN_THREAD. The effective group comes from ancestors, so the walk must resolve the effective group by checking ancestors. Checking the node's own default is not enough.
  
  **LOW**
  - **L1. ADR-0001 §2, `await get_tree().process_frame`.** Your UNVERIFIED claim is true, and it is worse than "outside the ordering". `SceneTree.process_frame` is emitted before any node's `_process`, so a resumed coroutine runs before the priority -100 Input Adapter.
  - **L2. ADR-0001 Implementation Guidelines, forbidden-clock lint.** `OS.get_unix_time*` does not exist in Godot 4 either. Name the real APIs: `Time.get_unix_time_from_system`, `Time.get_datetime_dict_from_system`, `Time.get_time_dict_from_system`. Consider adding `Engine.get_frames_drawn` and `Engine.get_process_frames` as well.
  - **L3. ADR-0001 Engine Compatibility, items (2), (3a), (3b).**
    - `Engine.time_scale` does scale `_process` delta, so the UNVERIFIED claim is true.
    - MainTimerSync does adjust the idle step, and `application/run/delta_smoothing` exists, so leaving it at default (on) still shapes delta.
