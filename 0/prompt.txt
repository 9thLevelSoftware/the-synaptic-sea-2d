     - D.12 hashes everything in one continuous stream, so a per-block incremental hash is impossible.
     - GDScript has no built-in 64-bit hash. Hashing about 150 KB in interpreted GDScript is estimated at 10–40 ms (spike S0-d measures it). That is too slow for the Debug Overlay's hash of every committed tick.
     - Proposal: hash each block separately, cache that hash, recompute it only when the block is dirty, then hash the per-block hashes (`H64(... H64(canonical_bytes(b)))`). Use Godot's built-in `HashingContext` SHA-256 truncated to 64 bits, or whatever S0-d shows is faster.

  2. **JSON cannot carry large 64-bit integers (S-1, a constraint on CR-8's "JSON-safe" wording).**
     - Godot's JSON parser reads numbers as floats, so integers above 2^53 do not survive. Kernel tick, seq and hashes are 64-bit.
     - The Graph's own values stay below 2^53. Its save form should be `var_to_bytes(allow_objects=false)` of its packed arrays, or base64-encoded packed bytes inside JSON.
     - Do not use Resources for saves: loading a `.tres` from a user-writable save is a code-execution risk.

  3. **Store integer, conserved quantities and derive the rest (ADR-LSG-02).**
     - Units: gas in mmol, heat in J, battery energy in mJ with power in W (one 100 ms step moves exactly `W × 100` mJ), fuel and coolant in mL, integrity in basis points (0–10000).
