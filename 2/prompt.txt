  ### Basis and limits
  
  - **No ADRs exist**, and `addons/` has no `plugin.cfg`, so gdUnit4 is not installed. Every testability claim is unproven.
  - **Budgets are stated but unmeasured.** OQ-10 and spike S1 say so themselves: P3 ≤ 2.0 ms and frame sim ≤ 4.0 ms (1 tick) or ≤ 6.0 ms (4 ticks) at P99 on a release export on RM-DESKTOP and RM-DECK. Graph hooks are ≤ 0.5 ms on a hook tick, and `emitter.place` plus exposure is ≤ 0.4 ms.
  - **The Deck frame ceiling is 30.0 ms and the desktop one is 14.9 ms.** The worst case (4 catch-up ticks, 6 ms) is 40 % of the desktop frame before rendering. LAG_FORGIVE_TICKS 0 drops the excess, so a slow tick degrades to slow-motion rather than a spiral. That choice is sound.
  
  ### (a) Hard or risky to implement in GDScript
  
  1. **Zero-allocation hot paths cannot be verified.**
     - TR-lsg-025 ("zero heap allocations per phase") and TR-cmd-032 ("0 kernel container allocations") have no direct GDScript measurement.
     - `Performance.OBJECT_COUNT` sees RefCounted objects but not Packed or Array buffers. `MEMORY_STATIC` is too coarse.
     - Rewrite these acceptance criteria as an OBJECT_COUNT delta plus a static-scan lint over the hot files. The lint bans `[]`, `{}`, `.duplicate()`, `Packed*Array()` constructors and `Dictionary` payloads. Otherwise the AC is unfalsifiable.
     - Alternatives that fit: a per-file "hot" marker that the lint keys off, or a canary test asserting OBJECT_COUNT is flat over N ticks.
  
  2. **Integer SoA performance is plausible but the evidence is missing.**
     - Typed local indexing of `PackedInt32Array`/`PackedInt64Array` has a fast path, but each cross-system accessor call and each `Callable.call` costs far more than the arithmetic around it.
     - Budgets that count accessor calls (`compartment_p(cid)`, `lit(ref)`, `rects_in`) will be dominated by call overhead, not data layout. Spike S1 should measure calls per ms, not only loop arithmetic.
     - GDExtension for the Graph is already named as rung 3, VS-A only. Keep it as the escape hatch, and note it breaks "GDScript only".
  
  3. **Integer-overflow hashing (H64 and mix64) has two hazards.**
     - `>>` is arithmetic in GDScript, so logical shifts need masking.
     - Hex literals above INT64_MAX do not parse. S0-b covers the literal; add the shift behaviour to the same spike.
     - The hash spec itself is ambiguous (OQ-8). Golden vectors must exist before ADR-0005 is Accepted, not after.
  
  4. **Typed-return override rule is likely a mislabel.** The 4.7 rule applies to overrides of a base-class method. The owner callables look like registered `Callable`s on `RefCounted` owners, not overrides.
     - The doc must say which it is: a virtual-method base class (`BlockOwner`) or free Callables.
     - If Callables, the 4.7 note is moot and the real enforcement is simpler: GDScript already rejects a typed function with a path that has no return.
     - KRN-CTX-06's "assert stripped on release" concern then reduces to one rule: the kernel must verify the returned token identity with a real `if`, never an `assert`.
  
  5. **Cyclic typed references between systems.** The dependency diagram shows Layout and Graph depending on each other (Layout consumes Graph `instantiate_section`; Graph consumes Layout room identity). Assembly, Interaction and Body also form loops.
     - GDScript tolerates cycles through `class_name`, but `preload` cycles fail to parse.
     - Mandate `class_name` plus typed interface base classes (`GraphMutators`, `LayoutMutators`) at the seams. Ban `preload` of sibling-system scripts, and lint it.

  Fix: add an `INIT` (or `LOADING`) phase. Either pass the scope as a parameter (`init_world(world_seed, scope, ctx)`) or carry it on `SnapshotContext`. State the `open_for` rule: all blocks during `init_world`, or the restoring block only if an owner's `restore` / `post_restore` uses its own mutators. Also say where that scope's dirty keys go; the "PROJECTOR notification" after a new game needs them. The merge can be left to ADR-0004/0016, but the scope must be defined here.
  
  ## B. Amendments required before Acceptance
  
  **B1. Fault-code packing does not work as written (§6, Key Interfaces).**
  - **Constants cannot carry the domain.** `domain_id` is assigned at runtime in registration order. But `const GRAPH_NOT_IN_SCOPE: int = 1` cannot be packed later, so the §4 example `return -FaultCodes.GRAPH_NOT_IN_SCOPE` returns the bare local code and `Faulted(code)` loses its domain.
  - **Codes shift between builds.** With ids assigned by registration order, inserting a system renumbers every later domain. That breaks log comparison, fixtures that assert `Faulted(code)`, and the "presentation maps codes" rule. It contradicts the ADR's own "append-only, never reused" intent.
  - **Recommendation:** give each domain a static id.
    - Each `*_faults.gd` declares `const DOMAIN_ID` and stores its codes already packed.
    - The signature becomes `register_fault_domain(domain_id, owner_name, names)`; a duplicate or out-of-range id fails boot.
    - The kernel holds one project-wide domain table (domain 0 = kernel).
  
  **B2. The FAULT_CODE table is still open (the lead-programmer's request).** architecture.md § Interface types still to define assigns to ADR-0003 "one closed enumeration per owning system, the kernel's own codes, and who may raise which". The ADR lists domain 0 with an ellipsis.
  - Close the kernel table here with values: `INCOMPLETE`, `NO_OUTCOME`, `STEP_OVERRUN` (if it is a fault at all; §8 calls 4 ms an alarm, so probably a diagnostic), `BINDING_REBUILD_CONFLICT`, `RESTORE_UNKNOWN_BLOCK`, `TICK_RATE_MISMATCH`, `RESTORE_EPOCH_RANGE`, `ACTOR_SOURCE_INVALID`, `COALESCE_DUAL_ORIGIN` and the capture error.
  - Close the violation-code set separately: `WRITE_OUTSIDE_SCOPE`, `PERCEPTION_READ_BLOCKED`, `SIM_WRITE_TRIPWIRE`, `CTX_DOUBLE_OUTCOME`, `HANDLE_UNREGISTERED`, `RESULT_HANDLER_DEAD` and the submit-during-SAVING code.
  - Assign each owner's domain id now. The owner's code list can wait for its system ADR, but "when its stories are written" is later than the architecture document planned.
  
  **B3. Class A return shape conflicts with architecture.md § API Boundaries.**
  - §5 says a Class A mutator returns `int` (`0` or `-code`). architecture.md has `weld_join(scope, plan) -> WeldResult {seam_id, opening_ids}`, and mutators that create entities must hand ids back.
  - Mandate one shape: either a caller-owned result object with a `status` field the caller must check, or `int` status plus a caller-owned out-buffer.
  - Also reconcile Class B. The ADR says it returns `0`; architecture.md shows `push_stimulus(...) -> void`.
  
  **B4. Class A/B under no rollback is sound but under-specified.** With no rollback, a fault leaves the touched blocks half-applied. That is acceptable only because FAULTED is terminal until a reload, and the kernel never autosaves in FAULTED; the ADR should say this explicitly. "Callers propagate" is not defined. Add:
  - **Fail-closed on the first fault:** the first `scope.fault` closes the scope, so later mutators write nothing and the dev-build diagnostics show the state at the fault. This is cheap and enforced by construction.
  - **Caller procedure:** on a non-zero status the caller returns `ctx.complete()` at once, with no further mutator calls and no second `ctx.fault` (the scope fault already counts).
  - **Link the two fault flags:** declare `WriteScope.faulted`. §5 says the kernel reads it, but §4 does not declare it. CR-19(a) also says `ctx.faulted` "includes any fault a mutator reported on the shared scope", so state how those two flags are linked.
  - **Leave OQ-15 open:** ADR-0021 still has the option to restore the four touched blocks on a weld fault. Say that `snapshot`/`restore` are the mechanism it would use and that nothing here rules it out.
  - **Scope-closed is not a fault:** in the §4 example, `open_for == false` is a violation (counted, not a fault, CR-9). Returning `-GRAPH_NOT_IN_SCOPE` to a caller that propagates it as a fault turns a violation into FAULTED in the paused cycle. Specify a distinct status (for example `STATUS_REFUSED`) that callers do not escalate, or state that escalation is intended.
  
  **B5. ADR-0002 conflicts on result and outcome handlers.** ADR-0002 Key Interfaces declares `set_result_handler(handler)  # (result: CommandResult) -> void` and an outcome handler `-> void`. GDD CR-19(a) lists result and subscriber handlers as kernel-invoked owner callables, and ADR-0003 says "No owner callable is declared `-> void`" and routes them through `NotifyContext`. One of the two ADRs must change. Recommended shape: `(result, ctx: NotifyContext) -> CompletionToken`. Also state whether `ControlOutcome` handlers fall under the same rule.
  
  **B6. Gaps between ADR-0003 and ADR-0001 / ADR-0002.**
  - **`submit_system` in `validate`.** It agrees with ADR-0002 §1, its Key Interfaces and the registry entry `system_command_submission` (HookContext and ApplyContext). But `validate` also receives `ApplyContext` while "submit_system and mark are not available there". Define how that works: a refused call counted under a named violation, or a separate `ValidateContext`. Remove "mark" (it lives on WriteScope, not the context). HookContext extends CallContext rather than ApplyContext, so give the shared submit surface one definition.
  - **CommandTypeDescriptor.** ADR-0002 says "this ADR defines the first nine; ADR-0003 completes the descriptor". ADR-0003 points back with "ADR-0002 fields + validate/apply". Each defers to the other. State the full typed field list once in ADR-0003 (field types: `allowed_origins` bitmask or array, `actor_binding` / `coalesce` enums, `actor_source: StringName`, `writes_blocks: Array[StringName]`, `payload_schema: Dictionary`, `validate` / `apply: Callable`).
  - **Where registration lives.** ADR-0002 puts `register_command` on `Kernel` ("Kernel, BOOTING only"); ADR-0003 puts it on `BlockRegistrar`. Pick one; the registrar forwarding to the kernel is fine, but say so.
  - **Facet name.** ADR-0001 has `setup(facet: ModuleFacet)` providing "registration and mutator-scope services". ADR-0003 delivers scopes per call and a `BlockRegistrar` that dies at the freeze. Name the relationship: BlockRegistrar is the boot-time part of ModuleFacet, or ModuleFacet is renamed. Say what a sim module keeps after the freeze. It also needs references to other owners' published mutators; state that the composition root wires those.
  - **binding_source twice.** It is a descriptor callable field (§2, as CR-6/CR-8 have it) and also `register_binding_source(...)`. Keep the descriptor field only.
  - **Diagnostics-channel registration missing.** CR-6 (via E-DO-38) and architecture.md § Initialisation order step 4 both register diagnostics channels in BOOTING; the registrar has no method for it.
  
  **B7. Interface types are incomplete for 15 owners to implement.**
  - **Context re-arm:** list everything reset per call (`completed`, `epoch++`, `faulted`, the ok/reject outcome, the `put` payload, the detail). Without it, a reused ApplyContext gives the second command in a batch a spurious `CTX_DOUBLE_OUTCOME`.
  - **Zero allocation:** "One scope per P2 apply and per P3 hook run" must say the scope objects are reused and re-armed like the tokens. A hook runs every tick, and allocating a scope per hook breaks the zero-allocation quiet tick (TR-cmd-032).
  - **`SimViews` / `PresentationViews`:** define the interface (`get(block_id) -> ?`). The "shared empty view" returned for a blocked PERCEPTION_OUT read, or after a `read_view` fault, will not satisfy a caller that casts to a typed facade, so it would become a script error. Either each owner supplies a typed empty facade (a descriptor field such as `empty_view`), or the return is nullable with a mandatory check.
  - **Descriptor types:** give each of `BlockDescriptor` and `HookDescriptor` a typed field list. **`class` is a reserved GDScript keyword** and cannot be a property name; rename it (e.g. `block_class`).
  - **Boot checks:** check `0 <= offset < divisor` at boot. Optionally check Callable validity and argument count at registration (`is_valid()`, `get_argument_count()`), so a wrong signature fails boot instead of surfacing as INCOMPLETE at runtime.
  
  **B8. `read_view` is called once at registration, which departs from the GDD without saying so.** CR-8 and CR-19(a) describe views obtained at render time and inside P2/P3. §7's long-lived facade is the better design but needs two things:
  - An explicit invariant: `restore` copies into the existing block object and never replaces it. If an owner swaps the object, every facade goes stale silently. Add a test.
  - A GDD-sync line. The CR-19(a) clause about a `read_view` fault inside P2/P3 no longer applies.
  
  **B9. The state table as specified does not match the GDD table and ADR-0002.**
  - **Bind and unbind would be ignored.** ADR-0002 routes `request_bind_seat` / `request_unbind_seat` through ControlHandle, and its IGNORED outcome is defined as "a pair the transition table does not list". They are not in the closed trigger set, so the composition root's boot bind would be IGNORED. Mark them non-transition requests, outside the table, or add rows that keep the state.
  - **`boot_validated` has no row.** The GDD goes BOOTING → LOADING directly on `request_new_game` / `request_restore`, with validation inside that boundary. With no row, the generated KRN-STATE-01 would expect an invalid-transition entry on every healthy boot. Make it an internal step of the serving boundary, not a trigger.
  - **The table needs more than plain targets:**
    - a `PRIOR` target sentinel for SAVING → prior state;
    - triggers for capture error, the boot-validation failure and teardown completion;
    - where DEFERRED sits relative to the table lookup (requests made during an atomic step).
  
  **B10. Kernel H1 allow-list.** The AC at GDD line 1076 fixes the Kernel's member variables. ADR-0003 adds `registry_valid`, the compiled schedule, the fault-domain table, contexts and tokens for each kind, the transition table and the scope objects. State that these live under `registries`, `kernel_state` or `diagnostics`, or list them for the allow-list review. Otherwise the first kernel story fails the lint.
  
  **B11. Dirty-key encoding takes ADR-0004's decision.** `key = (KIND << 32) | id` fixes ADR-0004's encoding and caps block-local ids at 2^32, while ADR-0002 treats ids as 64-bit. Declare the key an opaque `int` here and leave the layout to ADR-0004.

  ## D. Confirmed sound
  
  - **Epoch token:** it handles a null or default return, a token kept from an earlier call (`completed` is reset), and `complete()` called early before a later abort. Comparing by identity and epoch is at least as strong as the GDD's fresh token, without allocating. The epoch check is redundant with the reset of `completed`, but harmless.
  - **`registry_valid`:** a correct close of OQ-5. Splitting boot-failure FAULTED (shutdown only) from runtime FAULTED is right.
  - **Hook schedule:** with divisors 1, 5, 6, 12 the cycle C = 60; it is deterministic and printable. It matches architecture.md's hook table, except `transit.step`'s undeclared stale edge (IC-11), which will break the "warning list empty in CI" rule until the Web Map GDD declares it.
  - **Rejecting `@abstract`, Resource and Node:** correct for 4.7, the save-trust ruling and H10.
  
  ## E. Nits
  
  - **§8 wording:** "Boot asserts C ≤ 3,600" should read "fails boot naming the divisor", since the ADR bans `assert` for control flow.
  - **`writes_blocks`:** it is enforced only in PAUSED_APPLY. That matches the GDD, but say so, and consider checking it under STRICT_DEBUG while RUNNING to catch undeclared cross-block writes.
  - **Code example:** several `class_name` declarations in one code block is fine as illustration; note that each needs its own file.
