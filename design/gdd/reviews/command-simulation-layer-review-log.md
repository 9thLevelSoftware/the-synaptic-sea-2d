- [BLOCKING] CR-9 / Edge Cases L603-604, L616, L640, L647 / ACs L796, L832, L834, L855, L871, L873, L874: [systems-designer, godot-specialist, qa-lead, gameplay-programmer; confirmed by creative-director spot-check] The FAULTED model is built on exception semantics GDScript does not have. GDScript has no try/catch, a script error cannot be observed by the caller, and assert() is removed from release builds. As written, a release kernel never reaches FAULTED on an apply defect, so the infallible-apply contract and G5-on-defect cannot be enforced. About seven ACs cannot be run as (auto) in gdUnit4. The main review missed this, and it is the root under main BLOCKING #1.
- [BLOCKING] CR-5 result key and delivery / CR-4 seq / Edge Cases L574, L580, L589 / ACs L811, L817, L819, L821, L831: [systems-designer, qa-lead; confirmed by spot-check] together with [main review, gameplay-programmer] on delivery. (a) Identity: results are keyed (issuer_peer, seq) (L574, L811), but seq spaces are per (issuer_peer, origin) (AC L831), and host PLAYER and SYSTEM are both peer 1. The result field list (AC L819) has no origin. A DUPLICATE_SEQ rejection shares the original command's key. ACs L817 and L821 therefore cannot pass, and results cannot be routed. (b) Delivery: the GDD never says when P2 Applied/Rejected results are delivered. LOADING, FAULTED, SHUTTING_DOWN and idle PAUSED have no P5, so Dropped(RELOAD/SHUTDOWN/FAULTED) and NOT_ACCEPTING have no delivery point. AC L906 ('lag_ticks reads 56 ... decreases by 3 per frame (19 frames)') and AC L912 ('lag_ticks reads 0 afterwards, the excess is dropped') start from the same 1.000 s hitch and cannot both pass. CR-1 recommends Godot's physics callback (L55, OQ 2), yet D.5, LAG_FORGIVE, the pause-clear rule and these ACs all need a driver-owned accumulator, which the physics callback does not expose (L349, L944). The adopted CD note at L741 says lost time is 'never fast-forwarded', but a threshold of 30 still repays up to 30 ticks at 4x for about 10 frames. The accumulator is cleared only on PAUSED->RUNNING, so a load or autosave produces catch-up straight afterwards.

- [RECOMMENDED] CR-16 / CR-8 / CR-2 / D.4 / G1-G3 (paused service cycle): [main review, systems-designer, gameplay-programmer] Paused writes are guaranteed only by convention: there is no gameplay flag and no declared write-set. - [RECOMMENDED] CR-15 / States table / OQ 15: [main review, qa-lead, gameplay-programmer] Timing is undefined for control-plane requests made between ticks or from hooks and handlers. request_shutdown is ignored in BOOTING, LOADING and SAVING. - [RECOMMENDED] CR-4 / CR-7 / admission (L602, AC L822) / payload 'plain': [systems-designer, qa-lead, godot-specialist, gameplay-programmer] ORIGIN_NOT_ALLOWED is rejected at P2 even though origin is already known at admission (inconsistent with L612). allowed_origins, actor_binding, coalesce and max_age_ticks have no defaults, so an omitted actor_binding silently means no ownership check. - [RECOMMENDED] Formulas D.10 (rng_derive, mix64, fnv64): [main review, godot-specialist, gameplay-programmer, systems-designer] GDScript ints are signed and >> is an arithmetic shift. The SplitMix64 and FNV constants exceed int64 max, and the shifts inside mix64 are wrong without masking, not only the `unit` step. rng_int is undefined for lo > hi and for spans above 2^53.
- [RECOMMENDED] Formulas D.11 / D.12 / CR-8 kernel.clock / OQ 16: [main review, godot-specialist, performance-analyst, gameplay-programmer, qa-lead, systems-designer] The cost of state_hash is dominated by the GDScript canonical_bytes encoder, not by the hash function.
