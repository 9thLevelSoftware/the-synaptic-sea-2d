# Design Review Log — command-simulation-layer

## Review — 2026-10-27 — Verdict: NEEDS REVISION
Scope signal: L
Specialists: systems-designer, godot-specialist, qa-lead, gameplay-programmer, performance-analyst
Blocking items: 4 | Recommended: 15
Summary: Verdict: NEEDS REVISION, not MAJOR. The architecture is right. One authoritative tick, commands as the only write path, owner-held state and a write-only perception channel are what Pillar 1 ("The World Never Lies") and Pillar 4 ("Sanity Rewrites Reality") need. No specialist challenged that core, and I found no conflict with the pillars or the user decisions in force (chest lamp, glowsticks, lethal friendly fire, zoom, autosave restart).  What fails is that the spec was written for a language runtime other than GDScript, and that the document contradicts itself in four places. I checked each blocker in the GDD.  1. Prior verdict resolved: First review
Findings:
- [BLOCKING] CR-9 / Edge Cases L603-604, L616, L640, L647 / ACs L796, L832, L834, L855, L871, L873, L874: [systems-designer, godot-specialist, qa-lead, gameplay-programmer; confirmed by creative-director spot-check] The FAULTED model is built on exception semantics GDScript does not have. Spot-check confirms L604 'a thrown error in validate', L616 'If a hook throws', L640 'the exception is caught by the batch loop', L647 and AC L855 'snapshot() throws', and AC L873 'subscriber whose handler throws'. GDScript has no try/catch, a script error cannot be observed by the caller, and assert() is removed from release builds. As written, a release kernel never reaches FAULTED on an apply defect, so the infallible-apply contract and G5-on-defect cannot be enforced. About seven ACs cannot be run as (auto) in gdUnit4. The main review missed this, and it is the root under main BLOCKING #1.
- [BLOCKING] CR-5 result key and delivery / CR-4 seq / Edge Cases L574, L580, L589 / ACs L811, L817, L819, L821, L831: [systems-designer, qa-lead; confirmed by spot-check] together with [main review, gameplay-programmer] on delivery. (a) Identity: results are keyed (issuer_peer, seq) (L574, L811), but seq spaces are per (issuer_peer, origin) (AC L831), and host PLAYER and SYSTEM are both peer 1. The result field list (AC L819) has no origin. A DUPLICATE_SEQ rejection shares the original command's key. ACs L817 and L821 therefore cannot pass, and results cannot be routed. (b) Delivery: the GDD never says when P2 Applied/Rejected results are delivered. Admission rejects and Superseded fire synchronously inside submit(), which is re-entrant (L625 prescribes an immediate resubmit from a result handler). LOADING, FAULTED, SHUTTING_DOWN and idle PAUSED have no P5, so Dropped(RELOAD/SHUTDOWN/FAULTED) and NOT_ACCEPTING have no delivery point. SYSTEM results conflict with CR-10 'simulation systems never subscribe'.
- [BLOCKING] CR-1 / OQ 2 / Formulas D.5 / Edge Cases L621-622 / Tuning Knobs L721 / CD note L741 / ACs L905, L906, L907, L912: [main review, performance-analyst, gameplay-programmer, godot-specialist, qa-lead; confirmed by spot-check] Lag handling contradicts itself, and the contradiction sits on an unmade tick-source decision. AC L906 ('lag_ticks reads 56 ... decreases by 3 per frame (19 frames)') and AC L912 ('lag_ticks reads 0 afterwards, the excess is dropped') start from the same 1.000 s hitch and cannot both pass. CR-1 recommends Godot's physics callback (L55, OQ 2), yet D.5, LAG_FORGIVE, the pause-clear rule and these ACs all need a driver-owned accumulator, which the physics callback does not expose (L349, L944). The adopted CD note at L741 says lost time is 'never fast-forwarded', but a threshold of 30 still repays up to 30 ticks at 4x for about 10 frames. The accumulator is cleared only on PAUSED->RUNNING, so a load or autosave produces catch-up straight afterwards.
- [BLOCKING] Status header (L5-10) / Edge Cases preamble L574 / CR-16 / D.7 / AC preamble: [main review; qa-lead dissents and would rate this RECOMMENDED] The header says 'Status: Designed' and records CD approval. Yet L574 itself says the '(adopted - decision log 2026-10-25)' items 'require the user's call before being treated as spec'. That covers the paused service cycle, supersession timing, seq gaps, LAG_FORGIVE_TICKS and the STALE invariant, among others. The user has not audited the decision log. By the document's own definition these rules are not binding, so a programmer cannot tell which behaviours are spec. First-person authoring residue ('rejected by me', 'this agent') adds to the confusion.
- [RECOMMENDED] CR-16 / CR-8 / CR-2 / D.4 / G1-G3 (paused service cycle): [main review, systems-designer, gameplay-programmer] Paused writes are guaranteed only by convention: there is no gameplay flag and no declared write-set. The service cycle breaks D.4, G1, G2 and the 'tick >= queued_tick+1' AC. It is not reproducible from the command stream alone, and the paused boundary for control-plane requests is undefined. No MVP type uses the flag.
- [RECOMMENDED] CR-15 / States table / OQ 15: [main review, qa-lead, gameplay-programmer] Timing is undefined for control-plane requests made between ticks or from hooks and handlers. request_shutdown is ignored in BOOTING, LOADING and SAVING. Pause and restore are handled inconsistently in SAVING. LOADING->PAUSED conflicts with K-4. It is undefined whether SAVING can span frames.
- [RECOMMENDED] CR-4 / CR-7 / admission (L602, AC L822) / payload 'plain': [systems-designer, qa-lead, godot-specialist, gameplay-programmer] ORIGIN_NOT_ALLOWED is rejected at P2 even though origin is already known at admission (inconsistent with L612). allowed_origins, actor_binding, coalesce and max_age_ticks have no defaults, so an omitted actor_binding silently means no ownership check. 'Plain' payload has no Variant whitelist: NaN, cycles and mixed dictionary keys are not covered.
- [RECOMMENDED] Formulas D.10 (rng_derive, mix64, fnv64): [main review, godot-specialist, gameplay-programmer, systems-designer] GDScript ints are signed and >> is an arithmetic shift. The SplitMix64 and FNV constants exceed int64 max, and the shifts inside mix64 are wrong without masking, not only the `unit` step. rng_int is undefined for lo > hi and for spans above 2^53.
- [RECOMMENDED] Formulas D.11 / D.12 / CR-8 kernel.clock / OQ 16: [main review, godot-specialist, performance-analyst, gameplay-programmer, qa-lead, systems-designer] The cost of state_hash is dominated by the GDScript canonical_bytes encoder, not by the hash function. The hash also runs in release (K-4), contrary to D.11's 'debug only'. The PERSIST scope and PROFILE handling are wrong. Blocks have no length prefixes. kernel.clock's persistence and dirty status are unstated, so T is double-counted. snapshot(), restore() and read views do not require deep copies, so an MVP death-restart from one autosave can be corrupted by aliasing.
- [RECOMMENDED] CR-12 / H3-H5 / OQ 8 / read views: [godot-specialist, gameplay-programmer] Read views can return live Dictionary/Array containers that any reader can write to, with no scope check. P1 and P4 are therefore enforced by convention, lint and tripwire, not structurally as the main review's pillar check claims.
- [RECOMMENDED] CR-1 / CR-4 / Game Feel L749 / D.4 L_pixel / latency AC: [main review, systems-designer, gameplay-programmer, godot-specialist, qa-lead] The latency promises disagree: 17 ms in CR-1 against 33 ms in Game Feel. L_pixel double-counts the wait and leaves out interpolation delay. 'Movement never waits a tick / physics side' is false at MVP, where movement integrates in a P3 hook. The latency AC is measured at 16.7 ms frame resolution.
- [RECOMMENDED] D.6 / CR-2 P1, P2, P4, P5 / Performance ACs L931-934: [main review, performance-analyst, godot-specialist, gameplay-programmer, systems-designer] There is no frame-level sim budget. The 4.5 ms Graph example contradicts the 2.0 ms AC. P1 sorts every tick even though local admission order is already monotone. pop_front and the coalescing scan are O(n). P2 and P5 have no time budget, and P5 fires once per tick during catch-up. The prev/curr baseline roll at P4 has no owner. Perf ACs have no reference machine and would be run on debug builds.
- [RECOMMENDED] CR-4 coalescing / Edge Cases L589-590: [systems-designer, gameplay-programmer] 'Frozen' is ambiguous for overflow left after P1 truncation, so two intents with the same key can land in one batch.
- [RECOMMENDED] CR-9 / G4 / SYSTEM commands / D.8: [qa-lead, main review, gameplay-programmer] The pending queue is not snapshotted, so SYSTEM completions queued at P6 (weld/seam_cut) are lost on restore, and nothing obliges owners to be restart-safe. SYSTEM rejections cannot be seen by hooks. A divisor-1 hook resubmits duplicates while the queue is backlogged. The D.8 example arithmetic is wrong.
- [RECOMMENDED] Tuning Knobs coupled constraints / registry: [main review, systems-designer] Runtime-tunable knobs can violate assertions that are only checked at boot. Ranges disagree: max_age, MAX_DIRTY_KEYS, MAX_PAYLOAD, and the D.2 rate range. Six knobs have no registry owner entry: LAG_FORGIVE_TICKS, REMOTE_RATE_LIMIT, RATE_WINDOW_TICKS, SNAPSHOT_BUDGET_MS, MAX_BLOCKS and SYSTEM_RESERVE. Save/Load already cites two of them.
- [RECOMMENDED] CR-3 mismatched-divisor warning (L611): [systems-designer] The pair horror.step (divisor 5) after attention.step (divisor 6) triggers the warning on every real boot, which trains developers to ignore it.
- [RECOMMENDED] CR-10 subscribers / Interactions rows 2, 12 / AC L870: [qa-lead] 'Simulation systems never subscribe' contradicts Player Controller and Interaction acting as INPUT_SURFACE subscribers, so AC L870 would refuse them.
- [RECOMMENDED] Dependencies / Cross-References / Open Questions: [main review] These sections are stale. They mark 12 existing GDDs as unwritten, OQ 3, 5, 6 and 11 are already resolved, numbering is out of order, presentation consumers and Failure & Trail are missing, and Last Updated is out of date.
- [RECOMMENDED] Acceptance Criteria testability batch: [main review, qa-lead] Nine ACs are untestable as written (rewrites are in the main review's list), plus qa-lead's list: L786, L797, L802, L805, L817 (FAULTED and continue in one run), L835, L899, L910, L918. Coverage is missing for an invariant fuzz test, a 50-cycle save/load soak, two-process G3, a 129th block, and restore_after cycles. Integration-type stories are not tagged.

Findings:
- [BLOCKING] Status header L5-11 / Open Question 18 register (R-1..R-20) / OQ19, OQ21, OQ22: [main-review, confirmed by creative-director spot-check of L5-11] Ratification is still incomplete. L11 says the adopted/proposed items are 'not yet ratified by the user' and that the CD approval 'predates these amendments and has not been re-run'. The header at L10 still shows CD-GDD-ALIGN APPROVED 2026-10-25. That approval covers a different document from the current one: CR-1a, CR-5, CR-19 and D.5 were rewritten after it. Load-bearing behaviour still rests on unratified items: R-4 (the paused service cycle), R-11 (the Faulted terminal), R-13 (control-plane timing), R-15 (the payload whitelist), R-16 (the TickDriver), and OQ19 (the lag policy). Speaking as creative director, I do not regard the 2026-10-25 approval as covering this revision.
- [BLOCKING] CR-19(b) L150 vs CR-5 L93 / CR-8 / Edge Cases L687 / AC L910: [main-review, confirmed by creative-director spot-check] L150 says every owner callable 'ends with `return ctx.complete()`'. L93 still gives the signatures as validate(cmd, ...) and apply(cmd, ...) with no context object. validate must return OK or a domain reason, and snapshot must return its payload. A function's return value cannot be both the sentinel and that value. As written, this contract either cannot be implemented or quietly makes every validate and snapshot INCOMPLETE. In a release build, the sentinel is the only thing that catches an aborted script, and every owner GDD inherits the contract. A fix that introduces a defect like this has not closed prior BLOCKING #1.
- [BLOCKING] CR-4 seq (L84) / CR-5 / Edge Cases L639-642 / ACs L901-903 / Player Controller L106: [main-review, confirmed by creative-director spot-check] L84 defines seq as monotonic per (issuer_peer, origin), and L642 says SYSTEM seq is kernel-drawn. Nothing states who assigns seq for local PLAYER commands. Several INPUT_SURFACE handles share the (peer 1, PLAYER) stream: the input adapter, the Interaction prompt, the HUD and the Chart Table. If each keeps its own counter, legitimate input is rejected as DUPLICATE_SEQ, and the player sees the world ignore their action. That breaks Pillar 1's trust contract at the most visible point. In addition, submit returns nothing (L626), yet the Player Controller keys its pre-play tokens by seq at submit time.
- [RECOMMENDED] States and Transitions / Edge Cases L625, L714 / CR-16: [main-review] Some fault paths are missing from the state machine: PAUSED -> FAULTED for a fault in the paused service cycle, and init_world faults during LOADING. The return-from-SAVING-into-PAUSED admission rule also contradicts L625.
- [RECOMMENDED] CR-1a / D.3 tick_alpha: [main-review] tick_alpha falls to 0 whenever the kernel leaves RUNNING, so interpolated actors visibly snap back to the previous pose on pause. As creative director I rate this higher than a technical nit: it is a visible defect in the moment the player pauses to look.
- [RECOMMENDED] CR-8 interpolated / CR-2 P4: [main-review] The commit_baseline write in P4 contradicts the CR-2 rule that nobody writes in P4. The document does not say whether the baseline is canonical state (hashed, saved) or a derived cache.
- [RECOMMENDED] CR-12 / CR-19(e) STRICT_DEBUG tripwire: [main-review] Running a full uncached hash around every validate costs up to 128 hashes per tick, which makes the dev profile unplayable. The cached G3/G4 comparisons can also be defeated by a write that bypasses the dirty bit.
- [RECOMMENDED] CR-4 coalescing / D.8: [main-review] Supersession is committed before the later admission terms are checked, so a malformed or duplicate command can silence a valid one. The coalesce key also omits origin.
- [RECOMMENDED] CR-3 / CR-9 / Edge L624 / AC L854: [main-review] The document is inconsistent about whether an apply may call submit_system. CR-3 and CR-9 allow it only from hooks, but AC L854 submits from inside a P2 apply.
- [RECOMMENDED] CR-10 / CR-1a catch-up delivery: [main-review] Delivery of the merged presentation batch is unspecified when the catch-up loop exits early through a pause, restore or fault.
- [RECOMMENDED] States (NEW GAME) / CR-15 / CR-18: [main-review] There is no way to start a second new game within the same process. The user decision in force (MVP death = restart from last autosave) makes it likely the player hits this path through the menu. A full atomic LOADING runs in one frame with no hitch policy.
- [RECOMMENDED] CR-5 / CR-17 result buffer: [main-review] The result buffer has no bound, which contradicts CR-17's own rule of 'never unbounded growth'.
- [RECOMMENDED] Registry entities.yaml vs D.10 / D.12: [main-review] Registry text is stale. rng_derive still carries the arithmetic-shift form that D.10 fixed, state_hash still claims xxHash with a flat fold, and LAG_FORGIVE_TICKS, FRAME_SIM_BUDGET_MS, PAYLOAD_MAX_DEPTH and TICK_UNITS are not registered. The golden vectors themselves were verified correct.
- [RECOMMENDED] OQ20 / CR-1a cross-GDD: [main-review] Player Controller (L937, AC L990), Suit & Equipment (L1280) and Pixel-Perfect OQ10 still specify the physics callback as the tick source. Player Controller AC L990 would fail against the kernel as specified.
- [RECOMMENDED] ACs L905, L988: [main-review] Two ACs cannot run as written. L905 expects a frame that ends in LOADING or SHUTTING_DOWN, neither of which spans a frame. L988 expects RATE_LIMITED, but under the D.8 term order an ordinary type is rejected PAUSED first.
- [RECOMMENDED] Performance ACs L1019-1025 / OQ22: [main-review] The performance ACs have no pass/fail: the reference machine is TBD, the fixture is undefined, and a miss does not fail the suite. The four-tick budget assumes cheap ticks in a catch-up frame, which is not guaranteed.
- [RECOMMENDED] Dependencies / Quick reference / Open Questions: [main-review] Several sections are stale after the revision. The Dependencies prose says there are no soft dependents, then lists a Soft row. The Ship Body row still names the tick-alignment and physics-sampling hooks that were removed. The quick reference says 16 dependents while the table lists 25. Open Questions 4, 7, 9, 10, 12, 13, 14 and 17 have stale 'Resolve by' fields.
