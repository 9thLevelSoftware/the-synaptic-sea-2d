Findings:
- [BLOCKING] Core Rules IA-18 part reservation (L240) / Edge Cases B (L759) / AC-IA-30 / Player Fantasy Design Test 2 (L62): [game-designer][qa-lead, confirmed by creative-director spot-check of L240 and L759] The FULL-job reservation still leaves a cheap lie detector. A player presses, cancels at e = 7-10, walks away and reads the pack at until = Tb + 360. The part returns only if the module was truly healthy (a hallucination). The GDD calls this cost 'time and a held resource'. The player is not stationary, not lit and not loud while waiting, so the Pillar 3/P4 price (exposure plus TOOL noise) is about 2-3 % of the channel's. L759 claims 'No oracle', and AC-IA-30 pins the leak as correct behaviour, so a faithful implementation ships the oracle that Design Test 2 says must fail. This is the only place where the spec contradicts its own central invariant.
- [BLOCKING] Core Rules IA-30 / IA-14 row 9 / AC-IA-55 (L1285): [main review, agreed by game-designer and qa-lead] The record_falsification call site is 'apply'. AC-IA-55 literally says 'apply calls the Sanity mutator'. In this GDD apply runs at the begin tick, so Sanity would DEBUNK an active lie at e = 0, which is a free oracle at the press. The outcome argument only exists at completion. [game-designer] adds that the ledger-resume begin must not call it either.
- [BLOCKING] Core Rules IA-41 / UI Requirements (L1078, L1083) / AC-IA-64 (L1308): [ui-programmer] The HUD read contract cannot be implemented. The HUD may read only focus_view and channel_view. The spec still needs the hold-to-confirm fraction (L314 and AC-IA-64 say it is 'in neither view', and the HUD GDD names it as an open ASK to the Controller, so each GDD assumes the other publishes it), the Applied/Rejected/Dropped/Superseded result events with queued_tick (needed for ACK withdrawal), carry state for the drop prompt, and a second plate for HARDPOINT install versus drop. The V6 bar has no data source.
- [BLOCKING] Core Rules IA-9 (V7) / AC-IA-1 / AC-IA-41 / Open Questions 4: [main review] The MVP command set is undecided. AC-IA-1 enumerates the boot registry 'exactly' including top_up, while IA-9, LS-26 and Suit all defer V7 to a user decision. As written, AC-IA-1 fails for at least one document whichever way the decision goes. [game-designer][qa-lead] This is a scope decision that blocks only the top_up story. The creative-director agrees, so what this item requires is the conditional-AC edit, not the decision itself.
- [RECOMMENDED] Edge Cases C (L780) / Visual-Audio AD-11 (L929, L933) / Game Feel (L1035): [game-designer][qa-lead, creative-director concurs] An unpowered door plays a motor whine for 30 ticks. That is a false world statement and violates Pillar 1 (The World Never Lies), the section's own Serves pillar. The P4 rationale (uniform latency) is sound, but the cue chosen to satisfy it breaks P1. [ui-programmer] A deaf player gets no signal at all from a CLOSING_BLOCKED or NO_POWER door.
- [RECOMMENDED] Core Rules IA-10 / IA-14 row 3 (BUSY while octant != NONE) vs Player Fantasy L40-42, Game Feel L1053: [game-designer] The first press on a verb is usually made while walking toward the object. It is rejected BUSY with the dull 'no' cue, so the most-pressed input teaches 'stop first' through failure. The game-designer ranks this above the debounce issue. [ui-programmer] Rejects also produce a sub-perceptible ACK flicker that can exceed the 3 Hz ceiling when the player mashes.
- [RECOMMENDED] Player Fantasy anchor moment / V-3 (L918) / UI Requirements / HUD HS-37, HS-45: [main review] The fantasy promises the plate appears 'on the same frame' as the object, but a 9-tick debounce plus 20-tick spacing gives about 650 ms worst case at a breach. [ui-programmer] V-3 is also false for a second reason: lit(ref) is a per-subject, per-tick, hysteretic bit, while object visibility comes from the per-pixel shader. The bar also floats without a Ground backing when the plate hides mid-channel.
- [RECOMMENDED] Formulas D.8 / Core Rules IA-31 / AC-IA-52, AC-IA-106: [game-designer][qa-lead, independently agree] Harm escape is a cliff. Step 11 drops integrity below SUIT_LEAK_HP, which triggers a 30-tick STAGGER that freezes the victim inside reach, and every remaining step then lands. The carrying example (12 steps, 6000 bp) is actually lethal, and the real reaction window is about 41 ticks, not the 60 that D.8 implies. Lethal friendly fire is a user decision. A guaranteed-lethal harm for slow victims was never stated, and that touches anti-pillar 1 and the Pillar 2 tell window.
- [RECOMMENDED] Player Fantasy L42/L52 / IA-16 / D.1 / D.6: [main review][game-designer][qa-lead] 'Whatever you did stays done' / 'leaving is never punished' holds only for the first half of a repair. A resumed PATCH costs a fresh full bar for the tail, and cut, cap, crank and field-check progress expires after PARTIAL_TTL 10 s. Scaling D to remaining work would read hp and break IA-11c, so it is not an option.
- [RECOMMENDED] Formulas D.1 / anchor moment (L49-50) / PATCH_DECAY: [game-designer] 'Cancel at the hiss' is the dominant strategy, and its payoff is invisible. The leak is cured at about a third of the bar from hp 3000, and the hp_cap write-down already happened at step 1. The remaining two thirds buy about 190 s of extra life that no tell shows. This also cuts the Pillar 3 price of a patch. The real re-leak time is about 440 s, not PATCH_DECAY_S.
- [RECOMMENDED] Core Rules IA-18 (PATCH vs FULL selection) / Game Feel L1053: [game-designer] FULL is selected automatically whenever a part is stowed, so a player cannot spend a cheap patch on a minor leak and save the deep-derelict part. That removes the P5 resource decision and fails SDT Autonomy. [ui-programmer] 'Visible before the press' is false: nothing pre-press shows LONG or part consumption.
- [RECOMMENDED] Core Rules IA-17 healthy-subject guard / OQ 10: [main review][game-designer] The 6000 bp guard is arbitrary. A hallucinated-broken pipe at hp 4000-5999 is silent, so there is no consequence channel to warn the player, and patching it permanently writes hp_cap from 10000 down to 6000.
- [RECOMMENDED] Player Fantasy (L38, L48) / IA-33 / IA-30 vs OQ 32: [game-designer] The Pillar 3 price of working (noise, exposure) has no tell and no legibility AC. The scanner also dominates hand-checking as a way to resolve a lie, which the fantasy does not admit.
- [RECOMMENDED] Core Rules IA-24 / D.12 / States 6 / OQ 12: [main review][qa-lead][ui-programmer] Door attempt hazards: (1) CLOSING_BLOCKED has no exit and re-submits every tick. (2) A pending PLAYER OPEN can re-open a door that a SYSTEM cascade has just sealed. (3) attempts[] is keyed per face, so presses on both faces conflict. (4) I-8 is still open even though the Graph answers it with a binary area.
- [RECOMMENDED] Core Rules IA-17 self-patch / AC-IA-33: [main review] The only MVP repair path for a suit leak depends on the actor's feet being inside their own chest beam, and nobody owns that guarantee. It fails in the dark or with the beam off, which is exactly when a suit leak is most dangerous.
- [RECOMMENDED] Dependencies / Interactions / Overview neighbour status: [main review][qa-lead] Cross-references are stale. - [RECOMMENDED] Core Rules IA-37 / D.10 / OQ 30: [main review] The S4 loaded set (144) exceeds INTERACT_FIXTURE_BUDGET (120), and salvage-yield ITEM subjects are not budgeted.

Summary: My verdict on design/gdd/interaction-system.md is NEEDS REVISION, not APPROVED. Only targeted edits are needed. The design is sound, so there is no case for MAJOR REVISION.  All 8 sections are present. Every BLOCKING item from the first review is resolved in intent, including the FULL-job truth-branch oracle and completion-tick-only falsification. The design is coherent and its trade-offs are honest. The FULL-job commit rule (no refund after the first credited block, plus a 60 s grace) is the right Pillar 2 call: a refund would make interruption a free way to probe the truth.  The main review found no new blocker. I disagree on two of its findings, and both protect that same fix.  1. **IA-14
Prior verdict resolved: Partly
Findings:
- [BLOCKING] Core Rules IA-14 row 8 / IA-18 commit rule / D.7 / States 5 PAID row: [design-review main, escalated by creative-director] I checked line 217. It reads 'step (incremental channels: check_*, then the Class A mutator; others: blocks_done = j)'. Read literally, this never writes `blocks_done` for a FULL repair channel. Several other places depend on `blocks` (= blocks_done) being right on every channel: IA-18 commit/release at restore, the States 5 PAID row ('a cancel, abort or restore with blocks >= 1', line 403) and the grace anchor `t_last_block` (line 236). A faithful implementation can leave blocks_done at 0. The healthy branch then releases the part while the damaged branch has already spent it, which brings back the truth-branch oracle that the prior review's BLOCKING item closed. This is not editorial. The pillar-protecting fix from the last pass depends on it, and one sentence repairs it.
- [BLOCKING] Cross-References 3 / design/registry/entities.yaml (full_job_charge, harm_step, FIELD_CHECK_TICKS, TAP_REARM_TICKS): [design-review main, escalated by creative-director] I checked registry lines 3877-3901. `full_job_charge` still uses the retired absolute form 'RESERVED until = Tb + FULL_CHANNEL_TICKS (reuse: max(...))'. It also anchors the grace at `t_last_productive`, while the GDD now anchors it at `t_last_block` (line 236, 'so its length does not depend on module-body state'). A grace anchored on productive steps varies with hp, so it is itself a branch-dependent oracle. Item DB and Suit read the registry as `referenced_by` consumers, so their stories would build the oracle this review removed. `harm_step` also has no k_trap/t_trap. A GDD can pass review with an open question, but the project's source of truth must not contradict it on a pillar-level fairness rule.
- [RECOMMENDED] Player Fantasy (L53 stepping-away) / Design Test 1 / AC-IA-73b / FULL_JOB_GRACE_S: [design-review main; creative-director concurs, top creative priority] The fantasy promises that 'I can leave now' is true in every state. Under the new commit rule, leaving a FULL job after its first 100 ms spends a scarce part, and the player gets it back only by returning within 60 s. The trade itself is right: a refund would turn interruption into a free probe (line 785), and Pillar 2 honesty outranks generosity here. The problem is that the fantasy text no longer tells the truth about the price, and playtest is not set up to measure it. IA-16 already restates the honest cost of leaving for partial progress (line 224) but leaves out the part.
- [RECOMMENDED] IA-41 / States 1 / IA-14 row 9 / AC-IA-61, AC-IA-87: [design-review main] The terminal-state visibility rule contradicts itself. IA-41 says the state is held 'for exactly one committed tick'. States 1 (line 358) and AC-IA-87 (line 1275) say it goes to NONE 'in the same hook run'. AC-IA-61 cannot be observed as written.
- [RECOMMENDED] IA-41 press_blocked_moving (L321) / States 2 / HR-13 3 Hz ceiling / AC-IA-142: [design-review main; creative-director concurs] The bit is `octant != NONE` with no mode condition, so a door or breaker plate dims mid-stride even though TAP verbs are allowed while moving. That is a false tell, and it breaks the game's own rule that tells do not lie. With no hysteresis it can also flicker faster than the 3 Hz ceiling.
- [RECOMMENDED] IA-41 HUD read list / D.UI-1 / result-event projection / OQ 45: [design-review main] The closed HUD read list has leftovers. D.UI-1 reads begin_tick/T, which are not published. ACK is treated as a sim state. No owner is named for the reason-stripping projection. input_view, confirm_view and pressed(action) collide across the HUD, Controller and Interaction GDDs.
- [RECOMMENDED] IA-16 restore amendment (L224) / Edge Cases F / States 1 ABORT row: [design-review main; creative-director spot-check] A restore drops a half-made cut, cap, crank or field check with no ledger entry. IA-16's 'honest cost' sentence says these 'resume only within PARTIAL_TTL_TICKS', but after a restore they cannot resume at all. Edge Cases F and the States 1 ABORT row do not record this.
- [RECOMMENDED] OQ 10 / Dependencies Graph row / D.3 last_failure / IA-17: [design-review main] The hp-clamp answer is now upstream (Graph M7 refuses ABOVE_PATCH_CAP), but the GDD still lists it as open. D.3 lacks ABOVE_PATCH_CAP. M7's wording 'Interaction offers only FULL there' contradicts IA-11b, which requires an hp-blind offer. The silent-band hp_cap write is still live.
- [RECOMMENDED] IA-18 selector / D.7 offered / States 5 / amendment density: [design-review main; creative-director concurs] IA-18 carries two normative selectors: stowed_count and part_ready (part_ready does not exist in Suit). There are about 35 'Amended' paragraphs, so a reader has to reconstruct the live rule. That is a real implementer hazard in a 450 KB document.
- [RECOMMENDED] IA-24 / D.12 / Edge Cases C CLOSING_BLOCKED: [design-review main] For up to 300 ticks the player cannot cancel a PLAYER-origin door close, which contradicts its own rationale. A door shutting on the player's route with no recourse undercuts the player's sense of agency.
- [RECOMMENDED] Acceptance Criteria (untestable list): [design-review main / qa-lead domain] Ten ACs are subjective, process-based or owned by another GDD: AC-IA-136, 124, 102, 100, 2, 14(d), 93, 72, 121 and 117-120.
