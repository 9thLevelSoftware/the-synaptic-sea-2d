- [BLOCKING] Formulas F-12 / IDB-7 port table / Tuning Knobs (port 103, SEVER_O2_LOUD_MAX_PM): [main review] F-12 is a blocking CI lint that requires `p.cap >= rated_flow(p)`. [systems-designer] A per-port `rated_flow` column typed by the same author who typed the cap would make the lint circular, because IDB-7(b) already defines the cap as the rated flow. The lint only means something where an upstream value exists: R_SCR for port 101, R_VENT for 104, and the fuel burn for 402. - [BLOCKING] States and Transitions (instance-location table rows 1-13); IDB-13; IDB-21/IDB-22: [game-designer, confirmed by creative-director spot-check] The table at item-and-module-database.md:438-452 has no STOWED -> LOOSE_WORLD move. Boarding & Salvage records the same gap as ASK-BS-S1 and AC-BS-96 (boarding-and-salvage.md:1284, :1416): 'drop the plate first' is not performable. The Item DB states it 'defines the legal moves', so the omission belongs to this document. Three consequences follow. First, the Pillar 4(d) weight field check is blind while the only MVP HEAVY stowed item, the plate, is on the back (Suit SE-28 masking), and the player has no action that restores it. Second, parts and the 1-of-1 plate cannot move between crewmates, so 'who mends what is a crew decision' has no mechanism; a reactor FULL repair needing 2 kits on one seat can become unreachable in co-op. Third, the fate of a downed (not dead) holder's stowed stock is undefined. A dead crew is already covered by row 13 and the restart-from-autosave decision.
- [BLOCKING] IDB-15 (byte-form claim); AC-27, AC-28, AC-82; Open Question 20: [qa-lead, godot-specialist; both measured independently on the installed 4.7.2] AC-28 (BLOCKING, item-and-module-database.md:1205) uses `var_to_bytes` of the instance Dictionary as its stand-in. That encoding is about 176 bytes per instance and about 2.1 KB per 12-instance block, against limits of 64 bytes and 1024 bytes, so the criterion cannot pass. [godot-specialist] More seriously, `var_to_bytes` serialises Dictionary keys in insertion order. Two code paths that build the same instance (restore, pickup, salvage_yield) can therefore produce different bytes and a different `state_hash`, which silently desyncs a co-op replica. The 'canonical zeros' rule in IDB-15 does not prevent this. Save/Load SL-2 accepts `var_to_bytes(dict)` unless the owner publishes a canonical form, so no downstream check catches it.
- [RECOMMENDED] IDB-13 / F-13 (hull plate as a second carry slot): [main review, game-designer, qa-lead] The STOWED 30 kg `part_hull_plate` costs nothing in movement, so it acts as a free second carry slot. That undercuts the single-`carry_ref` haul bottleneck. [game-designer] A flat noise term is too weak, because carrying is already quieter per tile than running (48 vs 64). [qa-lead] No AC would detect a later regression either way.
- [RECOMMENDED] Player Fantasy anchor moment; F-11; AC-59/AC-93; Derelict Authoring DA-25: [main review, game-designer, economy-designer, qa-lead] The headline scrubber, machine-kit and earned-competence loop cannot be played in the MVP. Step 3 already admits the scrubber carry has no destination, and no `part_machine_kit` is placed. F-11 is a type-blind aggregate: it reports 714 permille 'in band' while machine-kit cover is 0. [economy-designer] When the uncovered-by-choice seam and the spare-breaker junction are removed from the denominator, real demand is 5 against supply 5, which is 1000 permille and above the band. [systems-designer] F-11 divides parts by repairs, and the reactor costs 2 parts.
- [RECOMMENDED] F-14 / F-15 / IDB-29 G-0 / AC-61 / AC-94: [main review, systems-designer, economy-designer, game-designer] F-15 compares the cost of one salvage cycle against the total patch chore over the horizon, which are not comparable. It also uses T_decay_cycle 540 s as the maintenance interval, but a life-critical scrubber goes into deficit after the 240 s hold, and duty wear makes it negative even sooner. That puts the chore load at about 2.25x the stated figure, which feeds directly into X-DA-9. F-14 is off by one at exact divisibility, and AC-61 encodes the wrong semantics; its UNDEFINED sentinel is not defined. [economy-designer] G-0 'always survivable with zero parts' holds only for N=1 in a 1-4 player game.
- [RECOMMENDED] F-1 / F-2 / Tuning Knobs (WEIGHT_MEDIUM_G, WEIGHT_HEAVY_G) / IDB-21-22: [systems-designer] Most of the published threshold ranges are infeasible against the shipped masses under the blocking margin lint. At WEIGHT_HEAVY_G 40000 the plate silently stops being HEAVY. The stowed-sum class has no margin or hysteresis, so a 200 g glowstick can flip the cue, and a full stack of ordinary parts can reach HEAVY at a legal knob value. [main review] Suit SE-28 masking and SE-41 reserved-part exclusion are not acknowledged. [game-designer] Three weight classes carry little information, and there is no calibration path before the lure.
- [RECOMMENDED] UI Requirements / IDB-21 (accessibility of the sole mass channel): [main review, game-designer] The weight check, the headline mechanic of Pillar 4(d), is audio-only. [game-designer] A redundant visual channel must itself be on the closed consequence list, or it can be corrupted and so becomes lie-able. That would break Pillar 1.
- [RECOMMENDED] IDB-18 (other runtime state on reinstall; battery discard): [main review] What reinstall does to scram, breaker_closed, fail_since_step, throttle_pm, setpoint_pp and similar fields is undefined. [game-designer] Resetting them to defaults is itself a free 'fix' action, the same shape as the launder. A battery that arrives empty has no diegetic cause, which is a Pillar 1 problem. [economy-designer] Reinstalled stores are near-worthless: a fuel tank has no refill path at all.
- [RECOMMENDED] Runtime representation: IDB-1, IDB-26, IDB-30; AC-03, AC-69, AC-85, AC-86: [godot-specialist, qa-lead] The GDD does not say whether defs and instances are Dictionary, RefCounted or Resource, yet AC-69 (no allocation) and AC-85 (immutability) depend on that choice. `make_read_only` is shallow. Catalogue tests need many instances per process, so a singleton or autoload would make them unrunnable. Refusals have no specified surface: assert is stripped in release, and push_error trips gdUnit4. JSON parsing loses precision above 2^53, and `parse_string` gives no error location. AC-86 cannot be satisfied because no listed AC emits ITEM_BOOT_MIRROR.
- [RECOMMENDED] Acceptance Criteria (structure, infrastructure and performance): [main review, qa-lead, godot-specialist] AC-32 bundles six or more behaviours. Several 'unit' criteria need the Graph. No gdUnit4 or CI scaffold exists. Literal counts (24 defs, next id 1014) break when a def is added. AC-99 asserts a suppressant verb that does not exist, and AC-22 forbids keys that AC-08 does not list. The radius boundary is only half tested. AC-82 misses clock-field holes. AC-69's 1.0 ms is self-contradictory, and the 10,000-call loop measured 15-17 ms on 4.7.2. OBJECT_NODE_COUNT can never change for a scene-tree-free catalogue. The review-type ACs (63-65, 96, 102) inflate the coverage figure.

A tool the player cannot verify reads as a lie or a bug. [game-designer, economy-designer] Scrap ignores value: a 1.5 kg lamp yields a scarce splice, and deliberate destruction becomes a parts factory that F-11 does not count. Glowsticks and suppressant have no demand model.
- [RECOMMENDED] IDB-6/IDB-8 (req_max, out_w_rated) / Tuning-knob range mismatches: [main review] `req_max` is missing for the scrubber and pump, and the 'inrush never clipped' rationale is false for the heater and lamp. [systems-designer] The reactor's 2500 W rating leaves out door motors, giving roughly a 5-10 percent margin, so lamps and heater would shed exactly when the crew seals doors. Several fields are missing from the snapshot/live classification. scrap_count 0 yields an illegal count-0 instance.
