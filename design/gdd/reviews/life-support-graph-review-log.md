Summary: Verdict: NEEDS REVISION. I spot-checked L108, L127, L196, L300, L361, L397-400, L517, L659, L791 and L829, and all confirm the findings. Findings:
- [BLOCKING] Formulas D.1/D.3/D.5, Edge Cases D5, LS-7 bands: [main review; systems-designer concurs; creative-director spot-checked L397-400 and L300] Nothing in the game produces inert gas. D.5 injects O2 only (`inj` is capped by `SP - p_o2`), the scrubber produces only O2, and n_inert changes only through D.1 exchange or venting. Total pressure can therefore only fall. After a patched breach a room recovers to about 210 dkPa at most, which is the DECOMP band, so ATMO_DECOMP stays live for the rest of the game. The D5 refill claim and the D.14 weld settle (about 613 dkPa) describe states the ship can never leave. This breaks Pillar 5 (loss is not total): one breach permanently damages the ship.
- [BLOCKING] D.2 seam weep / D.14 / D.15 (no SEAM-WEEP row); compounds the inert-gas gap: [systems-designer, rated RECOMMENDED; escalated to blocking by creative-director] The weld is the MVP must-prove. The area ceiling means wear-in does nothing until period 100. The weld example also ignores the even split. As a result a default weld drains 63-86% of a bay's gas before it tightens. D.2 claims '20 min to LOW', but the arithmetic gives about 2 min. The leak (about 840 mGU/step) is larger than a vent's 600 maximum, so pressure drops below DECOMP within about 12 min, and the inert-gas gap means it never recovers. A default player action is therefore lethal and permanent, which contradicts the document's own 'findable, fixable, not an emergency' intent and Pillar 5. Fixing the inert gas alone does not fix this.
- [BLOCKING] LS-11 mode 7 (L127, L791) vs D.11 worked example / fairness-gate AC / Edge Case 'rho >= 1317' / Tuning HP_OK: [main review; systems-designer and qa-lead concur; creative-director confirmed L127 'sev 1 from the first step'] OVERLOAD emits sev 1 from the first step, so the warning window opens on step 1. The D.11 example, its AC, the Edge Case and the HP_OK tuning cell all assume the window opens at hp < 7000 (warn_since_step 47). The fairness gate is Pillar 2's core guarantee, and its tests cannot be written while these sections disagree. [qa-lead] Also, at hp 3001 sev is probably 2, so this AC cannot exercise the gate_open clause at all.
- [BLOCKING] D.14 SEAL_STRAIN (L659) / LS-14 / HEALTHY AC (L1062): [main review; creative-director confirmed L659 has no EXTERIOR exclusion] Every closed OPENING with |dP| > WELD_DP_WARN emits SEAL_STRAIN. A closed exterior door (the airlock the V6 vent requires) holds 1000 dkPa against vacuum, so a healthy ship would CREAK and show rim frost permanently. That breaks the HEALTHY AC and 'a healthy ship never warns' (P1/P2). Note: SEAL_STRAIN came from an earlier CD-GDD-ALIGN amendment, so this defect started with a creative-director ruling.
- [BLOCKING] D.1/D.3/D.13 field maxima (L312, L361, L631-633), LS-24, restore range check: [systems-designer; creative-director confirmed L361 '0-3x10^7 mGU'] The documented gas maximum is ten times too small: P 1500 x V 200 x 1000 = 3x10^8. The registry's cryo bay (V 42) holds 4.2x10^7 at standard pressure. Because LS-24 clamps over-max values in release, and restore rejects them with GRAPH_RESTORE_OUT_OF_RANGE, the authored onboarding room would silently lose gas and every save containing it would be refused.
- [BLOCKING] D.9 hp floor (L517) vs D.11 / Edge Cases L772 / D.15 BREACH-EVENT: [systems-designer; main review had this as a minor range item; creative-director confirmed L517 `hp' = max(hp - dhp, floor_hp)`] The max() form can raise hp, and D.9 has no hull or seam floor (BREACH_HP). Applied literally, it heals a plate ruptured to 3600 back up to 4000 on the same run. That undoes exogenous damage and stops the headline BREACH-EVENT fixture from ever starting. The floor rule must only limit damage. As written it can heal.
- [BLOCKING] LS-21 persisted list / LS-8 phase 0 / M14, M15, M17 / Edge Case L829 / AC L1043: [godot-specialist; creative-director confirmed L108 and L196 (queued to next run's phase 0) and L829 (snapshot 'at tick boundaries')] The draw_air, set_load_request and deposit_trace queues hold state between hook ticks, but they are not persisted or hashed. Snapshots can happen on any tick, so a restore while a crew member is breathing drops a breath, a trace or a load change, and the restored run diverges from the uninterrupted one. MVP death means restart from last autosave, so restore is on the main death path and determinism must survive it. The existing restore AC passes only because it snapshots on a hook tick with no crew.
- [RECOMMENDED] D.7 HEATER / D.15 HEALTHY / Edge Cases L848: [systems-designer] The heater is a fixed 500 W load with no thermostat. Closing doors is the main decompression response, and with doors closed the heater room reaches HOT in about 8 min. So a healthy ship starts warning because the player did the right thing (P1/P2). The content lint may also reject the MVP template itself. Creative-director rates this the most important non-blocking item.
- [RECOMMENDED] D.5 / D.15 / R_BREATH (co-op crew count): [systems-designer] Every O2 balance figure assumes one crew. With 2 crew the scrubber runs at a net loss, and with 4 crew in a room O2-ROOM gives about 2.4 min against the 6-min R21 target. The game is co-op (Co-op Session is VS-B), so the margins need an explicit crew variable before co-op content is tuned.
- [RECOMMENDED] Edge Cases / Game Feel (SHIP-COLD, D6): [main review; systems-designer verified 40.7 min] An unpowered ship freezes every liquid pipe in about 41 min with no hull hole, which contradicts the text. This could make a good horror clock, but only if it is designed on purpose.
- [RECOMMENDED] D.15 CLT-LEAK, FUEL-DRIP; MVP-content AC (L1145): [main review] Integrated losses do not match the stated figures. Cavitation shuts the loop before the pipe fails. FUEL-DRIP nearly empties its tank. Which store a PIPE leak draws from is not defined.
- [RECOMMENDED] D.1 integer-floor pressure gradient: [main review] Taking dP from floored dkPa can reverse the flux near balance, which contradicts 'never overshoots' and the monotone-flux AC.
- [RECOMMENDED] D.6 / OQ 24 two-source islands: [main review] Edge load is undefined when two reactors share a welded island. That case is reachable in MVP (the weld must-prove).
- [RECOMMENDED] D.3 hysteresis / LS-21 / SEAL_STRAIN live bit: [systems-designer] Bands and SEAL_STRAIN hysteresis depend on earlier state that is not persisted, so a restored run can differ from a control run by one band step. That contradicts LS-21's own persistence rule.
- [RECOMMENDED] LS-21 / LS-1(e) conservation counters; D.5 pool cap: [main review; systems-designer] There are no produced_mgu, breathed_mgu or produced_dj counters, so conservation is only testable with all sources off. The O2 pool has no capacity and no overflow rule.
- [RECOMMENDED] LS-23 vs LS-11 (patch channel), OQ 23: [main review] It is unresolved whether a patch 'weeps' (consequence channel) or only reads WORN (Perception-corruptible). This decides whether a hallucination can hide a failing patch, which is a P1/P4 question.
- [RECOMMENDED] LS-26 / LS-18 V12 hand crank: [main review] V12 is an MVP verb, but the Graph has no interface for it.
- [RECOMMENDED] Dependencies / systems-index: [main review] There is a dependency cycle with Layout and Item DB, index edges are missing, Derelict Authoring and Ship Body have no rows, and several counts are stale.
- [RECOMMENDED] D.8/D.9 degenerate inputs; Tuning safe ranges: [systems-designer; main review] Several inputs can divide by zero (rho with cap 0, L_CAV_LO == HI, S_ext 0). batt_dis_cap is undefined. Several safe ranges include values the build assertions or the R21 bands reject. FREEZE_OFF has no assertion, and some starred knobs are not registered.
- [RECOMMENDED] Acceptance Criteria (evaluability): [main review; qa-lead] ACs contain unreachable values (4000/3950), a wrong field count (14 vs 15), an incomplete C/ trigger set, broken-breaker and pump-stall fixtures with no D.15 rows, mixed time units, a wall-clock cache test, an oracle for mutated snapshots that accepts any outcome, a literal-numeral lint, a bot search that cannot be enumerated, unclear fixture identities, no CI tiering, a ±3-point burst tolerance, and missing boundary-value tests.
- [RECOMMENDED] D.16 / LS-24 / S0-f / S1 performance framing: [main review; godot-specialist; performance-analyst] The coefficients are probably an order of magnitude low (realistic MVP estimate about 0.5-2.5 ms, not 0.36 ms). The '10 ms at 10 Hz' framing is wrong; the real constraint is a spike on one 60 Hz frame in six, shared with the other divisor-6 hooks. Hot-path allocations, read_view dictionaries, hash cadence and tombstone growth are not budgeted. No reference hardware exists (OQ-PF-25). S0-f cannot validate a twelve-phase model.
- [RECOMMENDED] LS-24 asserts / LS-1 Jacobi snapshot / LS-18 writer lint / S-1 serialisation / S0-b / integer-division warning: [godot-specialist] Several assumptions about GDScript do not hold or are unverified: assert is stripped from release builds and cannot be caught; packed arrays alias, so the 'start-of-phase snapshot' is unspecified; GraphState fields are public; the var_to_bytes(allow_objects) signature is Godot 3 era; H64 is a truncated SHA-256; arithmetic shifts and the large hex literal need tests; integer-division warnings will flood.
- [RECOMMENDED] Detailed Rules readability / cross-references / Open Questions: [main review] The document has 50+ inline amendment notes and cross-references that point to the wrong rule (LS-9/10, LS-13/14). The 18 vs 19 mutator count is inconsistent. It cites rationale tags that are not in the repo. OQ 1 is still open although the death rule is decided, and the Gaps ACs are stale.

## Review — 2026-10-27 — Verdict: NEEDS REVISION
Scope signal: XL
Specialists: none (lean re-review)
Blocking items: 5 | Recommended: 8
Summary: This re-review checked that the seven prior blockers are genuinely resolved, and I agree with the main review that the architecture is sound. The determinism contract, the integer units, the Jacobi exchange and the hysteresis persistence all serve Pillar 1 (the world never lies) directly. The tell-gated escalation serves Pillar 2. No MAJOR REVISION is warranted.  I spot-checked L66, L113, L1089, L1107-L1108, L1142 and the D.15 HEALTHY / OQ 34 text against the pillars in design/gdd/game-concept.md. Several defects are confirmed where the GDD's own acceptance criteria or exact invariants contradict its formulas: fuel 1000x against a 10^6 µmL unit, sev 3 against a computed 4, and g = 40,039,960
Prior verdict resolved: Partly
Findings:
- [BLOCKING] LS-1 (e) fuel invariant vs LS-8 phase 3 / Tuning FUEL_UML_PER_W (L66, L113, L1007, AC L1081): [game-designer/systems-designer, main review; confirmed by creative-director spot-check at L66 and L113] The exact-conservation contract is the backbone of every Graph test, and it is self-contradictory for fuel. LS-8 defines the burn in µmL with 1 mL = 10^6 µmL (120 µmL/W x 2500 W = 300,000 µmL = 0.3 mL). LS-1 (e) writes `1000 x (Σ stock_ml + Σ fuel_puddle_ml) + burned_ul − Σ fuel_rem`: a factor of 1000 and a counter named in µL. An implementer writing the exact-equality AC at L1081 either uses the wrong factor or guesses. I am raising this from RECOMMENDED to BLOCKING because a determinism invariant that every test asserts cannot be ambiguous.
- [BLOCKING] LS-16 / Edge Cases (RAGGED, L821) / AC L1142 vs D.4: [systems-designer, main review; creative-director confirmed AC L1142 reads 'hp 2500 with a sev-3 BREACH descriptor'] D.4 gives sev 4 at hp <= 2500, and hazard rules can only raise sev. As written the auto AC fails against the GDD's own formula. I am raising this to BLOCKING because a criterion that is guaranteed to fail is not a testable criterion.
- [BLOCKING] AC L1089 (exact-gradient arithmetic): [qa-lead/systems-designer, main review; creative-director confirmed L1089 states g = 40,039,960] The correct value is 14,000,999 x 40 − 28,000,000 x 20 = 39,960. A test that hard-codes the stated g fails. The conclusion still holds.
- [BLOCKING] Registry seam_at_weld / weld_quality and Modular Ship Assembly AC-MSA-18 vs revised D.2: [systems-designer, main review] The Graph owns seam_at_weld. Its revised D.2 milli-area floor now contradicts the registry entry (old ceil / 1e10 form, 'A_seam 2') and Assembly's AC-MSA-18 (12/2/2, should be 11,520/720/2 milli-units). GRAPH_HOOK_BUDGET_MS is also stale. Registered values that contradict their owner GDD produce a cross-system AC that will fail. This project's own process (the confirming consistency check) treats owner/registry divergence as a defect to close.
- [BLOCKING] D.15 HEALTHY row / OQ 34 / AC L1107-L1108 / Tuning T_SET_MC: [game-designer, main review; creative-director ruling requested] The HEALTHY row's headline ('any door configuration ... no descriptor at sev >= 1') contradicts its own tail and AC L1108, under which closed-door rooms reach COOL (sev 1) and FROST. The question is routed to me as OQ 34. My recommended ruling: cold behind a door the player closed is an intended physical consequence, not a 'warning' in the P1/P2 sense. Pillar 1 ('the room still gets cold') wants the world to answer player action honestly. 'A healthy ship never warns' means the ship raises no unprompted faults, not that it hides the results of the player's own choices. Suppressing COOL in sealed rooms (option b) would be a hidden exception and would break P1 legibility. This is the user's call, but the text has to agree with a ruling before Failure & Trail and the HEALTHY test can be finalised.
- [RECOMMENDED] D.16 / LS-24 / OQ 31 (performance): [performance-analyst/godot-specialist, main review] The central estimate of 1.7 ms for the MVP weld case is 3.4 times the requested 0.5 ms P99 share, the share is not yet granted, and reference hardware is undefined (OQ-PF-25). This is a real risk, but it is gated by spikes S0-S3 rather than being a design defect, so it is not a blocker for the design review.
- [RECOMMENDED] D.7 Output Range vs LS-7 / D.15 SHIP-COLD / Edge D6: [systems-designer, main review] D.7 still says pipes freeze only where a hole adds conductance. The revised design makes the 41-minute dark-ship freeze an intended clock. That clock is a Pillar 2 tell timeline, so the stale sentence would mislead tuning.
- [RECOMMENDED] Edge Cases L785 / D.15 BROKEN-BREAKER / LS-12 C2: [systems-designer, main review] '23 min to THIN' is actually the time for O2 to reach zero. No-leak THIN arrives at 3.3 min, HYPOXIC at 7.8 and ANOXIC at 12.2. Survival clocks drive the felt dread curve, so the error misstates the player experience by a factor of seven.
- [RECOMMENDED] LS-14 FailureDescriptor medium/acoustic mapping: [audio-director/gameplay-programmer, main review] There is no complete mode-to-(loop, medium, acoustic) table. OVERLOAD's 'the hum climbs' has no matching acoustic class. Pillar 2 depends on audible tells, so this mapping is design content, not an implementation detail.
- [RECOMMENDED] D.5 R_MAKEUP / BATT_DIS_CAP / stock_cap owner: [systems-designer, main review] The data owner of these fields is undecided, and they are absent from the Item DB.
- [RECOMMENDED] Acceptance Criteria L1126, L1140, L1168, L1176 and the untestable list: [qa-lead, main review] Four 'when written' criteria point at GDDs that now exist, several review-only and wall-clock ACs have no pass/fail, and L1209 is a hypothesis rather than a criterion.
- [RECOMMENDED] D.14 / LS-15 / D.15 SEAM-WEEP O2 band: [systems-designer, main review] 'Never leaves NORMAL' is true for band_p but not for band_o2 in the fixture.
- [RECOMMENDED] OQ 30, 35, 36 (open rulings): [game-designer, main review; creative-director view] On OQ 30, I recommend keeping free, demand-driven inert make-up at MVP. Pillar 5's scarcity pressure is carried by O2, fuel, scrubber wear and depletion. A finite inert reserve would add a bookkeeping loop with little dread payoff, and R8 already forbids extra managed loops at MVP. OQ 35 and OQ 36 are minor.
