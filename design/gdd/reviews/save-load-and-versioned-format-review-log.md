Summary: Verdict: NEEDS REVISION. The design is not wrong. The ring writer, the pre-check, the gate and the death stub are well conceived and honour the pillars. What is missing is a few decisions and contracts that targeted edits can supply. I checked the sections the verdict depends on and changed one of the main review's blockers.  The init_world 'no owner' blocker is stale. The kernel's CR-18/K-2, amended in today's consistency pass, already defines per-owner init_world steps and names Web Map & Transit WM-7 as the MVP world build. Save/Load's SL-18 and OQ-4 just never caught up, so this is now a RECOMMENDED text sync.  Three true blockers remain.  1. The 'never trapped' promise has a hole. Four
Prior verdict resolved: First review
Findings:
- [BLOCKING] Player Fantasy (L49); Detailed Rules SL-5, SL-6, SL-8; Formulas F-2, F-3, F-7; Open Questions OQ-1, OQ-22, OQ-40, OQ-41: [main review + game-designer + systems-designer + qa-lead, confirmed by creative-director at L1322] The promise in Player Fantasy that the game 'will never trap them in a moment they could not have seen coming' is not kept. A save made in a doomed but not-yet-DOWNED state is written as a normal, non-RISKY generation. The SL-8 step-back only fires for RISKY generations, so the death stub restores the doomed state every time. OQ-40's second option ('accepted exposure bounded by the RISKY step-back') is logically invalid [game-designer]: a doomed save is by definition not RISKY. A vitals gate alone cannot close the case [systems-designer]: a capture one tick before DOWNED, or a doom from hostile contact, breach or lethal friendly fire, still yields a non-RISKY restore with no agency. The Controller's DOWNED to IDLE recovery reopens the gate onto a still-critical seat [game-designer]. The QUIT path has the same hole [qa-lead]: `quit_write` checks only DOWNED/DEAD, and Continue has no step-back. F-2 is a registered formula whose inputs depend on this decision.
- [BLOCKING] Detailed Rules SL-12, SL-15 item 10; Tuning Knobs REBASE_BLOCKS (L583); Open Questions OQ-9, OQ-39 (L1321); AC-SL-65, AC-SL-67: [main review + qa-lead + systems-designer, confirmed by creative-director] The restore-idempotence contract is unresolved. OQ-39 itself states that a generation captured during CHANNELLING (a soft-gate state that QUIT bypasses) or inside Assembly's pending window 'verifies NOT_REPRODUCED in EXACT mode and halts a dev build', and that the interim fixes are 'not adopted in this pass'. So a routine quit mid-weld halts dev builds once those blocks register. The PC-17 wording also disagrees with itself: the knob row says the Controller now normalises in `snapshot()`, but the default is still `[controller.state]` and the SL-12 and SL-15 text still describe restore-time normalisation. While the list is non-empty, every real save verifies REBASED, so the G4 compare checks nothing. F-4 also writes a REBASED baseline that is never read back [systems-designer]. AC-SL-67 is a status statement and cannot serve as the merge gate [qa-lead].
- [BLOCKING] Detailed Rules SL-7 (L197), SL-10, T-4, T-8 step 2; Formulas F-2, F-5 (L611); Tuning Knobs RENAME_RETRY_COUNT row (L907): [main review + godot-specialist + systems-designer + qa-lead; game-designer would rate it RECOMMENDED] The death stub 'waits' for an in-flight write, and the text concedes that a write stuck in flush or re-read is 'unbounded in principle' (confirmed at L197, L611, L907). The wait sits at the DEAD boundary on the main thread. On Godot it cannot be a timed join: `Thread.wait_to_finish` and `WorkerThreadPool.wait_for_task_completion` take no timeout, and a blocking wait deadlocks if the worker reports back through `call_deferred` [godot-specialist]. Adding a timeout knob alone leaves the abandoned worker undefined. That worker can still hold `gen_k.tmp`, and `writer_busy` is a hard gate that never expires, so either two writers collide or every later autosave is silently disabled [systems-designer, godot-specialist]. This is not an edge-polish item. It decides the core shape of the writer's thread hand-off, and every implementer would have to guess it.
- [RECOMMENDED] Detailed Rules SL-18 (L255); Open Questions OQ-4 (L1303); AC-SL-75: [main review rated BLOCKING; creative-director downgrades] The main review says no one owns `init_world` and that the kernel has no such step. That is stale. Today's consistency pass amended command-simulation-layer.md CR-18 (K-2, L133, L158, AC at L845): every owner that registers an `init_world(world_seed)` runs it in `restore_after` order under one WriteScope, and the MVP world build is named as Web Map & Transit's `init_world` (WM-7). That matches Derelict Authoring's reading. The defect is that Save/Load's SL-18 and OQ-4 still call it 'Provisional' and route it to the kernel owner as an open question.
- [RECOMMENDED] Formulas F-5, F-4, F-8; Detailed Rules SL-16; AC-SL-87, AC-SL-89, AC-SL-91(a): [main review + godot-specialist + systems-designer + game-designer + qa-lead] The main-thread cost model is optimistic, and a hitch is itself a Pillar 3 information leak. Godot's HashingContext offers only MD5, SHA-1 and SHA-256, so `hash_algo` 0 (xxHash64) and 1 (FNV-1a) must be scripted per-byte loops. Estimates for that loop range from 15-60 ms [main review] to 50-150 ms [game-designer]. `t_walk` over 30-60k nodes is also likely to be 10-30 ms [systems-designer]. F-5 has no `main_hitch_ms <= SNAPSHOT_BUDGET_MS` check. A frame drop that occurs only on writes tells the player when the game saved and when the gate deferred. That is the same signal the retired UI-1 glyph was removed for [game-designer]. The 25 ms gate in AC-SL-87 and AC-SL-91(a) permits that drop.
- [RECOMMENDED] Formulas F-5, F-6, F-8; Tuning Knobs MAX_HEADER_BYTES, I7; AC-SL-87, AC-SL-120: [main review + systems-designer + qa-lead] The worked examples and the spike use 8 blocks (61 440 B), but the mandatory set is 14 blocks. The block-table record size of about 150 B is also too small for the defined JSON record, which is roughly 200-240 B. So F-6 sizes, the I7 floor and the MAX_HEADER_BYTES floor are all low. qa-lead notes that AC-SL-120 explicitly treats its constants as test inputs, so the B=8 case there is legitimate if labelled.
- [RECOMMENDED] Player Fantasy (L76); Game Feel; Formulas F-7; Tuning Knobs AUTOSAVE_INTERVAL_TICKS, LOSS_CEILING_TICKS, I9; AC-SL-55: [main review + systems-designer + game-designer + qa-lead] The loss ceiling of 5.5 / 6.5 min is overstated. (1) It assumes a healthy writer; with BACKOFF the loss is unbounded. (2) It is the discard per restore: net play lost across a step-back can reach about 41 400 ticks, roughly 11.5 min [systems-designer]. (3) The interval's documented safe range allows a loss of about 20 min, and I9 is only a diagnostic [game-designer]. (4) Once POD_ARRIVED and BERTHED events ship, the loss model changes completely [qa-lead, game-designer].
- [RECOMMENDED] MVP table (L33); EVENT_TRIGGERS; Player Fantasy anchor moment; Edge Cases M2, M3; OQ-25: [game-designer + qa-lead] The document never commits to whether event autosaves ship in the MVP. The anchor moment uses a weld EVENT save, but the default trigger set is `{NEW_GAME}`. If events ship, the interval is no longer the 'single lever' for death cost, and events become a learnable checkpoint grammar, the bonfire pattern the doc rejects. M3's response to quit-scumming ('raise the interval') has no effect on QUIT generations, and the Zomboid-parity justification is wrong because Zomboid deaths are final.
- [RECOMMENDED] UI Requirements UI-2; Visual/Audio newest-record line (L970): [game-designer; creative-director concurs on pillar grounds] The newest-record playtime line on the pause panel brings back the hidden gate meter that UI-1 was retired to prevent. Pausing is free, so a player can see that the record is overdue and infer that a tell is open, which breaks Pillar 3. The line also exposes the event-save grammar.
- [RECOMMENDED] Detailed Rules SL-6, SL-5; Formulas F-3; Edge Cases (Save & Quit and window close); OQ-25, OQ-42: [main review + godot-specialist + systems-designer + game-designer] The quit and close paths have several gaps. (1) The close mechanism (`auto_accept_quit = false`, a non-blocking WM_CLOSE_REQUEST handler, deferred `quit()`) is never specified. (2) The text contradicts itself on Alt-F4: L827 and OQ-25 list it as a process kill, but it raises the same close request SL-6 turns into a save. (3) It contradicts itself on hold versus exit after a timeout (L792 against SL-6 and AC-SL-45c). (4) Close while DOWNED, during LOADING and during SAVING are not covered. (5) A QUIT generation made inside an open Graph window shortens the warning. game-designer notes that main's proposed clamp runs the wrong way. (6) A RISKY QUIT generation lets an unrelated later death step back past it [systems-designer]. (7) Who tears down a session whose death stub found no loadable save is unassigned (OQ-42).
- [RECOMMENDED] Detailed Rules SL-23; Tuning Knobs SAVE_QUIT_TIMEOUT_MS, RENAME_RETRY_DELAY_MS; AC-SL-95a; harness seams: [qa-lead] SL-23 and AC-SL-95a forbid reading the wall clock in any decision, yet the quit timeout, the rename delay and the proposed death-stub wait are millisecond decisions made while T is frozen. AC-SL-95a would fail on behaviour the design requires. There is also no injected monotonic-ms seam and no manual-pump writer seam, so the interleaving tests cannot be deterministic.
- [RECOMMENDED] Detailed Rules SL-11, SL-14, T-5 steps 1 and 21; AC-SL-10..13, AC-SL-62, AC-SL-98: [qa-lead] (1) Before the first outside build, every newly registered block turns every dev save into MANDATORY_MISSING, so the files are quarantined as CORRUPT, which conflicts with SL-14's INCOMPATIBLE-dev path. (2) The origin of the golden v1 fixture is undefined. (3) A single transient open failure, typically an antivirus scan of the newest file, silently falls back to an older generation.
- [RECOMMENDED] Tuning Knobs invariants I1, I3, I6, I9; LOAD_MAX_ATTEMPTS; AUTOSAVE_RETRY_TICKS; F-2 backoff; OQ-28; AC-SL-38: [main review + systems-designer + qa-lead] (1) The documented safe ranges allow infeasible combinations: R in 721-900 with I = 3 600, and MIN_GAP above the interval minimum. (2) R = 0 divides by zero inside I3 before the invariant can report. (3) F-2 has no backoff term. (4) LOAD_MAX_ATTEMPTS can be set below AUTOSAVE_GENERATIONS, stranding an intact ring. (5) I6 is based on the wrong quantity. (6) The AC-SL-38 cases are unreachable or do not isolate one invariant.
- [RECOMMENDED] Detailed Rules SL-11, SL-7; Open Questions OQ-23; F-8: [main review + godot-specialist + game-designer] The DEAD tick does main-thread file I/O for the pre-check. The fix proposals differ: main suggests pre-staging at DOWNED entry; godot-specialist suggests a hot RAM copy of the payload kept after WRITTEN; game-designer notes that pre-staging is invalidated by a DOWNED to IDLE recovery.
- [RECOMMENDED] Kernel transitions (LOADING to RUNNING, SAVING to prior); Game Feel; AC-SL-91: [godot-specialist] No GDD says what happens to the tick driver's wall-time accumulator across the stalls Save/Load creates. The first frame after a restore can therefore run a burst of up to MAX_TICKS_PER_FRAME ticks.
- [RECOMMENDED] Detailed Rules SL-12, K-4; Open Questions OQ-6; AC-SL-58..60: [main review + qa-lead] The release-build reproduction compare needs K-4, which does not exist yet.
- [RECOMMENDED] Detailed Rules SL-7, SL-21 restore_reason; Game Feel #2; UI-6/UI-7: [game-designer; this is a creative call that needs the user] After a death the player gets no indication of what was lost. A silent rewind of up to 5.5 min looks the same as a crash or a corruption fallback, which harms the SDT competence need.
- [RECOMMENDED] Player Fantasy (L64); Detailed Rules SL-23; Edge Cases L806, L829; OQ-37: [game-designer] Determinism is sold as the carrier of Pillar 5's knowledge and condemned as the scouting exploit, but it is one mechanism. Attention and Horror restore exactly, so after a restore a repeated path replays the same ambush, which undermines Pillars 2 and 3.
- [RECOMMENDED] Dependencies; Interactions; Cross-References: [main review] Dependencies are not bidirectional. Adaptive Audio & Tells and Derelict Authoring cite Save/Load but have no rows. Summary: Verdict: NEEDS REVISION, narrowly. I agree with the main review's verdict and with all 15 non-blocking findings. Spot-checks of OQ-1 (L1336), OQ-40 (L1368), the Dependencies paragraphs (L859 and L861) and the SL-2 interchange call (L177) confirmed the findings the verdict depends on.  There is one true blocker, and it is a user decision rather than a drafting defect. The doc can still restore the player into a death they cannot avoid: a non-RISKY capture just before DOWNED, a recovery onto a critical suit, or QUIT-then-Continue with a critical suit. That breaks the promise of Pillar 5 ('Loss Is Not Total') that loss is bounded, and turns Pillar 2's dread into a loop the player cannot act on.

Findings:
- [BLOCKING] Detailed Rules SL-5, SL-6, SL-8; Formulas F-2, F-3, F-7; Invariant I9; Open Questions OQ-40 (L1368), OQ-41: [main-review][creative-director, confirmed by spot-check of L1336 and L1368] The doomed-autosave exposure is still open, and only the user can close it. OQ-40 now states the problem honestly. The invalid 'bounded by the RISKY step-back' option is gone, and the Player Fantasy was narrowed to 'never records a moment it could have warned you about'. Even so, F-2 has no vitals input, F-3 steps back only from a RISKY generation, and there is no post-DOWNED refractory. That leaves three paths that restore the player into a death they cannot avoid, with no agency: a non-RISKY capture one tick before DOWNED, a DOWNED-to-IDLE recovery onto a critical suit, and QUIT-then-Continue with a critical suit. The doc itself says this blocks the autosave_gate and generation_select stories. In creative terms this is a pillar problem as well as a rules problem. A save that replays an unwinnable death breaks Pillar 5 ('Loss Is Not Total'): the loss stops being bounded and becomes a loop. It also turns Pillar 2's dread into helpless repetition. It is not a drafting defect, so the fixer was right not to adopt the package alone, because it changes the meaning of the user's rule 'MVP death = restart from last autosave'.
- [RECOMMENDED] Open Questions OQ-40 draft AC-SL-128: [main-review][creative-director concurs, verified at L1368] The draft criterion contradicts itself. Once the seat is DOWNED the hard gate holds and DEAD follows in 1,800 ticks, well before the 7,200-tick cap, so the 'cap generation is RISKY' clause can never be reached in that scenario.
- [RECOMMENDED] design/registry/entities.yaml vs GDD: [main-review] The registry was not refreshed after the revision. It still has REBASE_BLOCKS = [controller.state], the old interval and min-gap ranges, six stale formula expressions and example numbers (90 020 B and 3 960 B header in the GDD versus 63 284 B and 1 800 B in the registry; 139.7/179.1 ms versus 128.7/146.1 ms), and several constants are not registered. The registry is the project's source of truth, so this drift will mislead stories. It matches the known pattern where fixes to the owner GDD and the registry leave leftovers.
- [RECOMMENDED] SL-7, SL-11, T-5 step 1, T-8; READ_RETRY knobs: [main-review] The death-stub hand-off contradicts itself on the disk-fallback path. The text requires restore at the same DEAD boundary, yet also allows read retries polled across frames. The main-thread hitch on the DEAD tick also has no bound.
- [RECOMMENDED] F-5 vs T-4 / SL-11: [main-review] The SHA-256 hashing is counted on the worker in F-5, but T-4 assembles the hashed header and trailer on the main thread. The Pillar 3 hitch gate is therefore under-counted.
- [RECOMMENDED] Tuning Knobs I2, M1, AC-SL-38: [main-review] The joint lower bound from I2 and Attention's registered lint makes the effective interval floor 7,500 ticks, not 5,400. M1's response is the only 'players are stuck' lever, and as written it would trip I2 at boot.
- [RECOMMENDED] T-6 crash-recovery row 2; SL-3; AC-SL-110: [main-review] Roll-forward can resurrect an abandoned-timeline .tmp because the epoch is not durable. That reintroduces the ghost timeline the epoch exists to prevent, and it is a determinism and trust risk the player would read as the game lying (Pillar 1).
- [RECOMMENDED] SL-10 writer thread contract: [main-review] There is no exit rule for a hung abandoned worker. Thread.wait_to_finish has no timeout, so the player's own Save & Quit or window close could hang.
- [RECOMMENDED] SL-2, OQ-5 (K-3), AC-SL-06: [main-review][creative-director concurs; L177 and L1350 confirm the call is written as var_to_bytes(..., allow_objects = false)] In Godot 4, var_to_bytes and bytes_to_var take a single argument and refuse objects, and the object forms are the separate *_with_objects functions. The flag shape is from Godot 3, so the AC-SL-06 lint would be vacuous.
- [RECOMMENDED] Game Feel 1; F-5; AC-SL-87, AC-SL-91(a), AC-SL-131: [main-review] A 16.7 ms capture budget plus an absolute 16.7 ms frame cap cannot both hold. Pillar 3 forbids exactly the dropped frame this allows.
- [RECOMMENDED] OQ-39; Interaction and Assembly GDDs; AC-SL-67: [main-review] The REBASE_BLOCKS contract is resolved in this GDD, but the owners have not acknowledged it. Assembly E-29 contradicts SL-25 on whether last_result persists, and the AC-SL-67 debt waiver has no expiry.
- [RECOMMENDED] Dependencies L859, L861: [main-review][creative-director, verified] L861's 'exactly one runtime system' contradicts the Upstream table and SL-13's runtime reads. L859 keeps the stale authoring-time status list in front of the refresh note.
- [RECOMMENDED] SL-7 orchestrator ruling tail; F-4 verdict; SL-3/F-9 slot freeing: [main-review] Three smaller gaps. Superseded ruling text still sits inline next to the live SL-7 rule. The F-4 verdict expression has ambiguous nesting. A slot holding a file that failed only as FILE_UNREADABLE could be overwritten by the next autosave.
