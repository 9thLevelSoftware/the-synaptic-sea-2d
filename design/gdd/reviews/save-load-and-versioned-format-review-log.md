- [BLOCKING] Player Fantasy (L49); Detailed Rules SL-5, SL-6, SL-8; Formulas F-2, F-3, F-7; Open Questions OQ-1, OQ-22, OQ-40, OQ-41: [main review + game-designer + systems-designer + qa-lead, confirmed by creative-director at L1322] The promise in Player Fantasy that the game 'will never trap them in a moment they could not have seen coming' is not kept. A save made in a doomed but not-yet-DOWNED state is written as a normal, non-RISKY generation. The SL-8 step-back only fires for RISKY generations, so the death stub restores the doomed state every time. OQ-40's second option ('accepted exposure bounded by the RISKY step-back') is logically invalid [game-designer]: a doomed save is by definition not RISKY. A vitals gate alone cannot close the case [systems-designer]: a capture one tick before DOWNED, or a doom from hostile contact, breach or lethal friendly fire, still yields a non-RISKY restore with no agency. The Controller's DOWNED to IDLE recovery reopens the gate onto a still-critical seat [game-designer]. The QUIT path has the same hole [qa-lead]: `quit_write` checks only DOWNED/DEAD, and Continue has no step-back. F-2 is a registered formula whose inputs depend on this decision.
- [BLOCKING] Detailed Rules SL-12, SL-15 item 10; Tuning Knobs REBASE_BLOCKS (L583); Open Questions OQ-9, OQ-39 (L1321); AC-SL-65, AC-SL-67: [main review + qa-lead + systems-designer, confirmed by creative-director] The restore-idempotence contract is unresolved. OQ-39 itself states that a generation captured during CHANNELLING (a soft-gate state that QUIT bypasses) or inside Assembly's pending window 'verifies NOT_REPRODUCED in EXACT mode and halts a dev build', and that the interim fixes are 'not adopted in this pass'. So a routine quit mid-weld halts dev builds once those blocks register. The PC-17 wording also disagrees with itself: the knob row says the Controller now normalises in `snapshot()`, but the default is still `[controller.state]` and the SL-12 and SL-15 text still describe restore-time normalisation. While the list is non-empty, every real save verifies REBASED, so the G4 compare checks nothing. F-4 also writes a REBASED baseline that is never read back [systems-designer]. AC-SL-67 is a status statement and cannot serve as the merge gate [qa-lead].
- [BLOCKING] Detailed Rules SL-7 (L197), SL-10, T-4, T-8 step 2; Formulas F-2, F-5 (L611); Tuning Knobs RENAME_RETRY_COUNT row (L907): [main review + godot-specialist + systems-designer + qa-lead; game-designer would rate it RECOMMENDED] The death stub 'waits' for an in-flight write, and the text concedes that a write stuck in flush or re-read is 'unbounded in principle' (confirmed at L197, L611, L907). The wait sits at the DEAD boundary on the main thread. On Godot it cannot be a timed join: `Thread.wait_to_finish` and `WorkerThreadPool.wait_for_task_completion` take no timeout, and a blocking wait deadlocks if the worker reports back through `call_deferred` [godot-specialist]. Adding a timeout knob alone leaves the abandoned worker undefined. That worker can still hold `gen_k.tmp`, and `writer_busy` is a hard gate that never expires, so either two writers collide or every later autosave is silently disabled [systems-designer, godot-specialist]. This is not an edge-polish item. It decides the core shape of the writer's thread hand-off, and every implementer would have to guess it.
- [RECOMMENDED] Detailed Rules SL-18 (L255); Open Questions OQ-4 (L1303); AC-SL-75: [main review rated BLOCKING; creative-director downgrades] The main review says no one owns `init_world` and that the kernel has no such step. That is stale. Today's consistency pass amended command-simulation-layer.md CR-18 (K-2, L133, L158, AC at L845): every owner that registers an `init_world(world_seed)` runs it in `restore_after` order under one WriteScope, and the MVP world build is named as Web Map & Transit's `init_world` (WM-7). That matches Derelict Authoring's reading. The defect is that Save/Load's SL-18 and OQ-4 still call it 'Provisional' and route it to the kernel owner as an open question.
- [RECOMMENDED] Formulas F-5, F-4, F-8; Detailed Rules SL-16; AC-SL-87, AC-SL-89, AC-SL-91(a): [main review + godot-specialist + systems-designer + game-designer + qa-lead] The main-thread cost model is optimistic, and a hitch is itself a Pillar 3 information leak. Godot's HashingContext offers only MD5, SHA-1 and SHA-256, so `hash_algo` 0 (xxHash64) and 1 (FNV-1a) must be scripted per-byte loops. Estimates for that loop range from 15-60 ms [main review] to 50-150 ms [game-designer]. `t_walk` over 30-60k nodes is also likely to be 10-30 ms [systems-designer]. F-5 has no `main_hitch_ms <= SNAPSHOT_BUDGET_MS` check. A frame drop that occurs only on writes tells the player when the game saved and when the gate deferred. That is the same signal the retired UI-1 glyph was removed for [game-designer]. The 25 ms gate in AC-SL-87 and AC-SL-91(a) permits that drop.
- [RECOMMENDED] Formulas F-5, F-6, F-8; Tuning Knobs MAX_HEADER_BYTES, I7; AC-SL-87, AC-SL-120: [main review + systems-designer + qa-lead] The worked examples and the spike use 8 blocks (61 440 B), but the mandatory set is 14 blocks. The block-table record size of about 150 B is also too small for the defined JSON record, which is roughly 200-240 B. So F-6 sizes, the I7 floor and the MAX_HEADER_BYTES floor are all low. qa-lead notes that AC-SL-120 explicitly treats its constants as test inputs, so the B=8 case there is legitimate if labelled.
- [RECOMMENDED] Player Fantasy (L76); Game Feel; Formulas F-7; Tuning Knobs AUTOSAVE_INTERVAL_TICKS, LOSS_CEILING_TICKS, I9; AC-SL-55: [main review + systems-designer + game-designer + qa-lead] The loss ceiling of 5.5 / 6.5 min is overstated. (1) It assumes a healthy writer; with BACKOFF the loss is unbounded. (2) It is the discard per restore: net play lost across a step-back can reach about 41 400 ticks, roughly 11.5 min [systems-designer]. (3) The interval's documented safe range allows a loss of about 20 min, and I9 is only a diagnostic [game-designer]. (4) Once POD_ARRIVED and BERTHED events ship, the loss model changes completely [qa-lead, game-designer].
- [RECOMMENDED] MVP table (L33); EVENT_TRIGGERS; Player Fantasy anchor moment; Edge Cases M2, M3; OQ-25: [game-designer + qa-lead] The document never commits to whether event autosaves ship in the MVP. The anchor moment uses a weld EVENT save, but the default trigger set is `{NEW_GAME}`. If events ship, the interval is no longer the 'single lever' for death cost, and events become a learnable checkpoint grammar, the bonfire pattern the doc rejects. M3's response to quit-scumming ('raise the interval') has no effect on QUIT generations, and the Zomboid-parity justification is wrong because Zomboid deaths are final.
- [RECOMMENDED] UI Requirements UI-2; Visual/Audio newest-record line (L970): [game-designer; creative-director concurs on pillar grounds] The newest-record playtime line on the pause panel brings back the hidden gate meter that UI-1 was retired to prevent.
