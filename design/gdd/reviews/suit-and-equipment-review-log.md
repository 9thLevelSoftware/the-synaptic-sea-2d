Findings:
- [BLOCKING] Detailed Rules SE-7 / Formulas D.2, D.9 / Tuning TOPUP_MODE (L1010) / OQ-2; life-support-graph.md OQ 20 (L1186), LS-26: [main review + systems-designer, spot-checked by creative-director] Two GDDs disagree on the MVP top-up mode. Suit ships TOPUP_MODE VERB as the default (L1010). The Graph's OQ 20 (L1186, owner: user) says 'Until decided Suit runs TOPUP_MODE PASSIVE with CELL_ENABLED 0', and V7 is missing from the Graph's LS-26 MVP verb list. The PASSIVE path also cannot be built as written. D.2 (L520-531) has no credit term for the granted extra. Its shortfall = pending_draw_mgu - granted_prev means a room that grants exactly R_BREATH debits the reserve by the very amount being topped up. D.9 (L795) sets request = R_BREATH + extra. So the default on paper (Graph) is the mode that is broken in the formulas (Suit). This choice decides whether the lamp cell and the Pillar 3 'go dark' lever exist at MVP, so it is a scope decision for the user, not a tuning detail.
- [BLOCKING] Detailed Rules SE-14/SE-15 / OQ-34 / Cross-Refs L1349; horror-entities.md C-HE-6, AC-HE-124 (L1040): [main review + ux-designer, spot-checked by creative-director] Horror's C-HE-6/AC-HE-124 (a BLOCKING creative-director position) says tool_suppressant leaves the MVP start kit. Suit declines (L1349: 'C-HE-6 ... is not applied here'). Horror's own knob table already describes SUPPRESSANT_START_CHARGES as 'moot at MVP once the item is removed'. The two designed GDDs contradict each other on slot 4, the charge count, the A8 assertion, AC-SE-16/17 and an asset row. ux-designer adds that at MVP this is a false affordance: a visible, equippable, depleting tool with no registered verb and no defined use-press feedback. It also reads as a defence tool, which works against the anti-pillar 'the suit has no weapon' and against Pillar 1 (no hidden or effectless stats).
- [BLOCKING] Detailed Rules SE-35 / Tuning STAGGER_WINDOW_TICKS (L1069) / AC-SE-36 (L1467) / OQ-11 (L1536): [qa-lead, escalated from main's RECOMMENDED; creative-director agrees] The only live external-stagger trigger, 'a two-band pressure drop within STAGGER_WINDOW_TICKS', appears 7 times in the GDD and has no formula anywhere in D.1-D.11. It has no persisted state (SE-38 has no band_p history), no rule for compartment crossings or SE-3's NONE-to-EXPOSED switch, and no behaviour across restore. OQ-11 marks it live at MVP, and the Controller has registered the SYSTEM stagger with Suit as submitter. AC-SE-36 is an auto BLOCKING criterion whose oracle would be invented by whoever implements it. Stagger is an input lock on the player, so an underspecified trigger is a fairness defect (Pillar 2) as well as a test gap.
- [RECOMMENDED] Formulas D.3 cap bound / D.4 / SE-17, SE-20 / AC-SE-19: [systems-designer; not in main review] The cap bound ('the FULL-to-WALK_ONLY edge recurs at most once per HOLD_12 runs per axis') is false for warmth. The warmth rung follows |L| with no hold, and TL_HYST is only 300. A seat moving back and forth through a doorway between a lethal-cold room and a COMFORT room cycles 3700 to 4000 in 8 runs, so the Controller stagger fires about every 3.3 s against a documented 10 s floor. This produces stagger spam at doorways, which hurts game feel more than any other numeric defect in this review.
- [RECOMMENDED] Formulas D.8 build assertions A2/A4/A5 / Tuning Knobs / SE-18: [main review + systems-designer + qa-lead] The assertion set is tight at the defaults. On the heat side, the time from first body cue to FAILED equals SUIT_MIN_WARNING_S exactly. A2 vs A4 pins RUNG_MIN_TICKS at exactly 600, so the published '300-900' range is false. A5 ignores the leak, and at LEAK 300 it drops below W_MIN_WARNING_S. No sweep proves the Pillar 2 floor across the knob ranges.
- [RECOMMENDED] AC-SE-34 / Edge Cases (doomed autosave) / Save/Load OQ-40: [main review] An autosave can capture a seat at CRITICAL. Under the binding user rule 'MVP death = restart from last autosave', that can produce a repeat-death loop. AC-SE-34 fails by its own statement. qa-lead adds a related path: a data retune of R_BREATH/RESERVE_S hard-fails every saved restore (AC-SE-49), which leaves the player with no loadable save at the moment of death.
- [RECOMMENDED] Formulas D.4 / SE-20 / Edge Cases Warmth / AC-SE-22d: [main review, re-graded by systems-designer] In the FREEZING strip with e == 0 there is no relax. The invariant 'can never walk-lock' is therefore false, and AC-SE-22d writes the stall into the spec. The seat can still walk out to FROST, so this is not a literal soft-lock.
- [RECOMMENDED] Formulas D.10 cold_side / D.10 breath cue / view(): [main review] cold_side stays true when residual cold load enters a HOT room, so the player sees rime and shivering in a hot room, which is a dishonest body channel (Pillar 1). Breath cadence, the primary cue, has no level definition and is missing from view().
- [RECOMMENDED] AC-SE-8 vs SE-5/SE-6; SE-38 pending_draw_mgu range; D.9 BATTERY rounding: [main review + systems-designer] These are ledger contradictions. AC-SE-8 omits the shortfall debit. The pending_draw_mgu range is too narrow for PASSIVE. On a BATTERY port, a 1-unit grant credits 0 ticks, which contradicts AC-SE-9's 'exact' invariant.
- [RECOMMENDED] UI Requirements L1307-1308 / SE-30: [ux-designer] When the reserve engages, it becomes the death clock, but it sits on the corner panel. The central strip keeps showing a room p_o2 of 0 in cyan while the player is breathing fine, and the warning mark changes position depending on breath source. This is a structural defect in the contract Suit hands the HUD.
- [RECOMMENDED] Visual/Audio / UI / OQ-20, OQ-36, OQ-37; adaptive-audio AA-41/42: [main review + ux-designer + qa-lead] Deaf and hard-of-hearing players have no non-audio witness for the valve click, breath cadence, MEDIUM load, heat STRAINED-to-CRITICAL, or the audio-first stagger. design/accessibility-requirements.md does not exist. The fairness of the death clock (Pillar 2) currently depends on hearing.
- [RECOMMENDED] Player Fantasy / Game Feel / (no onboarding entry): [ux-designer] As specified, the player learns the cue vocabulary by dying and losing up to 20 minutes. Nothing guarantees that a player's first reserve engagement, first thin-air breath or first cold exposure happens where it is survivable. The cell warning (20 s on a 20-minute resource) is too short to plan around.
- [RECOMMENDED] Detailed Rules SE-8 / Edge Cases: [main review + qa-lead] The case 'lamp cell empty far from the ship' has no stated outcome: which verbs still work unlit, whether doors are passable. A home-ship refill costs about 4 % of a cell, which is nearly free, so the Pillar 3 cost is not felt.
- [RECOMMENDED] Acceptance Criteria (multiple): [main review + qa-lead] About 15 ACs are compound, snapshot-based, disjunctive or statistically unsound: AC-SE-7, 12, 19, 20, 22d, 28, 42, 43, 47, 48a/b, 53, 1a/1b, 38, 83, and the unnumbered AC-FEEL block. The stated count of 83 understates the real number of test cases by about 3x. There is no mapping from ACs to stories or gate levels, and no rule for what NOT ASSESSED means on a BLOCKING review item.
- [RECOMMENDED] Dependencies / OQ-12, OQ-17 / Appendix D / document structure: [main review] The Graph's M15/M16 confirmations have landed but are still listed as open. systems-index row 10 is missing the declared edges. There is stale Phase-5 text, unresolvable R-/CK- citations, and decision history mixed into normative rules across 370 KB. Cue levels are restated in 5-6 places and have already drifted.
