## Summary
Over a hundred requirements from seventeen GDDs (the 65 rows of `tr-baseline.md`, the TR-saveload-028 to 042 gap rows and the cross-system rows the traceability matrix assigns here) need a save file that is self-verifying, written without ever endangering a good generation, versioned from the first build, and paired with a per-slot `restore_epoch` that re-keys threat draws on death without letting quit or death be a reroll oracle. This ADR fixes one container (8-byte magic, JSON header, `var_to_bytes` block payloads, SHA-256 trailer), a ring of three generations written by one `Thread` per job that the main thread only polls, a two-level version scheme (container migrated by Save/Load, blocks by their owners), a reserved PROFILE side file in the same container (built at the first PROFILE block, not at MVP), and a `restore_epoch` held in two alternating checksummed files that is made durable before every `request_restore`. The service is a tree-free `RefCounted` in `src/save/`; a thin `SaveHost` node in `src/game/` polls it once per frame and owns the window-close interception. Settings persistence is out of scope.

## Context

### Problem Statement
The game's one failure consequence is death and restart from the last autosave (Pillar 5), and its horror depends on the player never being able to read the world through the save system (Pillars 1, 3, 4). That makes persistence unusually load-bearing: a bad write that costs a good generation destroys the campaign; a pause when the game saves tells the player a tell has closed; a restart that replays the identical threat draws makes death a free retry; a restart that lets quit choose the draws makes quit a reroll oracle; and a format that cannot be migrated strands every outside tester at the first schema change. The Save/Load GDD settles the behaviour and defers a dozen mechanism choices to "the atomic write, backup and thread model" ADR and to "the container ADR": what the bytes are, how a Windows rename is used safely, how a worker thread is owned, how a quit is waited for, how the 64-bit and JSON constraints are met, where `restore_epoch` lives and how it reaches the kernel, and whether the snapshot hitch is acceptable. Two probes (§ Engine Compatibility) also falsify two GDD sentences: `var_to_bytes` does encode objects, and `FileAccess.open` is not exclusive. Without one decision, each of the 14 persisted blocks would meet a slightly different container, and the first outside build would find the differences.

### Constraints
- **Save/Load registers zero state blocks and zero hooks** (SL-17, TR-saveload-018): ring bookkeeping must live outside the world, or it rolls back with a restore.
- **Exactly one thread boundary** exists (architecture § Data Flow 7): the save writer. `Thread`, `WorkerThreadPool`, `Mutex` and `Semaphore` are allowed only in `src/save/` (ADR-0010 IO-02), and `call_deferred`, `set_deferred`, `call_thread_safe` and `Engine.get_main_loop` are banned in `src/save/` as everywhere else in the foundation layers (SIM-12); this ADR cites those rules and does not restate them. The only cross-thread payload is a `PackedByteArray` (or `PackedInt64Array`) **handed over by value and never mutated by either side afterwards**, plus pre-globalised absolute path strings, ints and a header template built for the job (TR-saveload-007; § 1.6 states the ownership rule, because the engine does not enforce one).
- **Capture is synchronous inside the kernel's `SAVING` state** at a tick boundary (TR-cmd-017, TR-saveload-009); `SAVING` is atomic within one boundary service and never spans a frame (ADR-0003 § 9, ADR-0001 § 1).
- **A bad file never produces `FAULTED`** (TR-saveload-014): the pre-check is a pure function of `(bytes, registry view, build constants)` and runs before the kernel is touched.
- **Block objects are `RefCounted`, restore copies into the existing object** (registry `block_as_resource_or_node`; ADR-0003 § 2). No `Resource` or `.tres` path, ever (a script can ride in one).
- **Integer-only simulation** (ADR-0005); JSON parses numbers as `float` (probed), so no 64-bit or hashed value may travel as a JSON number (S-1).
- **No wall clock in any sim decision** (kernel H9; ADR-0010 SIM-02): every millisecond I/O timeout in this ADR (`WRITE_JOB_TIMEOUT_MS`, `SAVE_QUIT_TIMEOUT_MS`, `DEATH_STUB_WRITE_WAIT_MS`, `RESTORE_EPOCH_WRITE_MAX_MS`, `RENAME_RETRY_DELAY_MS`) reads the injected `Clock` port (`src/kernel/ports/clock.gd`, `now_us()`; `FakeClock` in tests) and changes no sim state (SL-23). The one wall-time value, `created_unix` and the time `SaveInfo` displays, comes from the `WallClock` port (`src/save/wall_clock.gd`, `now_unix() -> int`; sole implementation `src/game/system_wall_clock.gd`, ADR-0010 TD-11), injected into `SaveService.setup()` only. It is display metadata and is **never** an ordering key (the generation number is the only order), a gate, a hash input or a sim input.
- **No autoload or static singleton** (registry `kernel_autoload_or_global`): Save/Load is constructed and injected by the composition root.
- **Fault codes** follow ADR-0003 § 6: `(DOMAIN_ID << 16) | local`, domain 1 = `save_load`, append-only.
- **Single player at MVP**; co-op replication, guest carry-over and Steam Auto-Cloud are later tiers and constrain only the path layout.

### Requirements
- One container format for WORLD generations and the PROFILE store, self-verifying by a trailer that lives outside the header.
- A write that never overwrites in place, never deletes a generation before its successor verified, never blocks the main thread, and never starts while the kernel is `FAULTED`.
- A load that classifies every failure (corrupt, incompatible, owner-failed, not-reproduced) and decides the next action from the class.
- Two-level versioning with an obligation to migrate that begins at the first outside build, and development saves that are refused rather than half-migrated.
- `restore_epoch` that survives a process kill, a lost manifest and a step-back, is durable before the restore that uses it, and reaches the sim only as an argument.
- A quit that waits for its write by polling, with a timeout, and never hangs the process on a stuck worker; the window close button, Alt+F4 and OS shutdown take the same path (§ 1.6).
- A recorded ruling on the snapshot hitch (OQ-14) and a named spike for every engine claim the reference does not source.

### 1. The container and the write path

**1.1 Layout.** The file layout is SL-1 as written: 8 bytes of magic, `u32` LE `header_len`, UTF-8 JSON header, concatenated block payloads, a 32-byte SHA-256 trailer over every preceding byte (the **format law**: for every layout, forever, the last 32 bytes of any file bearing the magic prefix hash `[0, size - 32)`). Choices this ADR adds:

- **Magic.** `53 59 4E 53 45 41 1A` (`"SYNSEA"` and a SUB/EOF byte, so a text-mode tool stops early), then the container-layout id byte (`01` for `FORMAT_VERSION` 1). The file extension is `.sav`.
- **Streamed hashing, scoped.** Save/Load's own `HashingContext` (`HASH_SHA256`) use is limited to `payload_sha256`, the trailer and `registry_epoch`, fed in chunks (`update`) so no hash needs a second whole-file copy; **`update` is never called with a zero-length chunk** (it errors), so an empty payload or header is skipped. `state_hash` and every `block_state_hash` are computed by the **kernel, uncached, during the `SAVING` capture** (ADR-0005 §§ 4.7, 5.4) and arrive in the snapshot outcome; Save/Load never computes or re-derives an `H64`. Container byte layout (`encode_u32` for `header_len`, `slot_epoch` bytes) and integrity hashing in `src/save/` use the byte writers that ADR-0005 § 1.7 row 8 forbids in the kernel, sim and block owners; `src/save/` is exempt because that output never feeds `H64` or `state_hash` (TD-12). Reading a candidate checks `FileAccess.get_length()` against `MAX_SAVE_BYTES` first, then reads. Whole-file reads use `get_buffer` loops or `FileAccess.get_file_as_bytes`; both are acceptable, the length cap comes first.
- **One payload form.** Every block payload is `var_to_bytes(dictionary)` of the owner's plain-data snapshot **Dictionary**; that every persisted block `put`s a Dictionary is a Save/Load-side precondition checked by the type walk (the decoded root of each block must be a `Dictionary`), not a change to ADR-0003's `put(payload: Variant)` signature. **Canonical bytes are produced by the kernel (ADR-0005 § 3.1) and never stored:** the Graph's snapshot payload is a Dictionary of named packed arrays; storage is `var_to_bytes`; hash input is ADR-0005's TLV of the same payload. The GDD's second form ("the owner's own canonical byte form as raw bytes", SL-2) is **dropped as a container form**. Reason: one decode path, one type walk, and a restore hand-off that is always a `Dictionary`, matching ADR-0003's `restore(data: Dictionary, stored_version, ctx)` (no `form` field and no byte-blob hand-off shape to invent). State equality is `state_hash`, never file bytes (probed: insertion order changes the bytes).
- **Header** is the closed list of SL-1 plus the additions of § 2 (`catalogue_version` is already there). The per-block hash field is named `block_state_hash` (SL-16) throughout, beside `enc_len`; the header `state_hash` is the kernel's `state_hash(PERSIST, T)` from the capture outcome. `seats` is an array of `PlayerId` ints (MVP `[0]`): non-empty, unique, in range, covering every PER_PLAYER key; no peer id, binding table or controlled-entity table is stored, and the kernel rebuilds bindings after a restore (TR-saveload-037). `created_unix` is written from the `WallClock` port and is display metadata only. Unknown extra keys are ignored when `min_reader_version` is satisfied; a missing required key refuses.

**1.2 Interchange and the trust model (corrects SL-2).**

1. **The encoder does not refuse objects (probed).** `var_to_bytes` silently encodes an `Object` as an `EncodedObjectAsID` and `bytes_to_var` returns it. SL-2's wording "the form that does not encode objects" is wrong in the direction that matters: a stray object in a `snapshot()` would reach disk. The defence is therefore **not** the encoder. It is (a) the type walk, which rejects `TYPE_OBJECT` explicitly (an `EncodedObjectAsID` is an Object), and (b) the write-side `VERIFYING` stage, which decodes and walks the bytes the worker just wrote (T-4), so an object-bearing snapshot is caught at write (`SL_WRITE_UNENCODABLE`, previous generations intact) and never first at a death.
2. **Decode with `bytes_to_var` only.** `var_to_bytes_with_objects` and `bytes_to_var_with_objects` are forbidden outright, as are `Resource`, `.tres`, `.res` and `ResourceLoader` for any save path. `bytes_to_var` of hostile input returns `null` and logs an engine `ERROR` that code cannot suppress (probed): so the decode runs only **after** the trailer, the block table and `payload_sha256` have passed, and a `null` result for a block that must be a `Dictionary` is `SL_PRECHECK_BLOCK_DECODE_FAILED`. A forged file with correct hashes can still produce engine error lines; that is a tamper case, accepted, and the fuzz suite is told (Risks, ADR-0010 assumption).
3. **Allowed types, enforced by the walk, not the encoder (probed: `Vector2i` round-trips, so the ban is policy).** `null`, `bool`, `int` (full 64 bits, § 1.3), finite `float`, `String`, `Array`, `Dictionary` with `String` or `int` keys, and the packed arrays `PackedByteArray`, `PackedInt32Array`, `PackedInt64Array`. Forbidden: `Vector2i` and every vector or rect, `Color`, `Object`, `Callable`, `Signal`, `RID`, `NodePath`, `StringName` as a key or a value (a `StringName` is decoded as one, probed, so it must be rejected, not coerced; ADR-0003's `StringName` block ids and the in-memory staged payload keys of § 3.6 are memory-only and never enter a file, where block ids are header `String`s), and non-finite floats. Typed `Array[T]` and `Dictionary[K, V]` **round-trip their values** through the encoder (probed; type preservation is not asserted), which settles SL-2's "untyped until the spike" note: snapshots may use typed or untyped containers; the walk checks the decoded element types either way. Bounds: `MAX_DECODE_DEPTH` 16, `MAX_DECODE_NODES` **provisional 100 000** (the GDD knob is 250 000; typical saves are 10 000 to 30 000 nodes and the bound stays lowered until the walk timing of SAVE-WRK-1 f is measured, then is raised only as far as that timing allows; a packed array counts as one node, unchanged), per `MAX_BLOCK_BYTES` and `MAX_SAVE_BYTES`. Owners' `restore()` still validates meaning; the walk validates only type and size.
4. **JSON appears only in the header and in the dev-only `dump-save`.** A dump renders any `int` whose magnitude is at or above 2^53 as a lowercase decimal string and any `PackedByteArray` as `Marshalls.raw_to_base64`; it is diagnostics, never a load path (TR-lsg-022).
5. **No compression** in the MVP (`codec` 0; 1 reserved). A size alarm at `SAVE_SIZE_ALARM_BYTES` 2 MiB is diagnostics only.
6. **Roots and staging.** The decoded root of every block must be a `Dictionary`, and the in-memory staged payload of § 3.6 is built from those. `Dictionary.make_read_only()` on a staged payload is **shallow** (probe 14): it is a convenience, never a guarantee, and owners must still copy what they keep. A deep read-only snapshot, where an owner wants one, is built by the owner from `duplicate(true)` at capture.

**1.3 64-bit values.** Two rules, one per medium.

- **Header (JSON).** Every value that can reach 2^53 (`T`, `world_seed`, `state_hash`, each `block_state_hash`, `registry_epoch`) is an exact-width lowercase `hex64` string (16 chars): by ADR-0005 § 4.2 the **8 little-endian bytes of the `int`**. Save/Load calls `Hex64.encode(int)` and `Hex64.decode(String) -> Hex64Result` from `src/shared/det/` (`save` may import `shared`, ADR-0010) and defines **no 64-bit codec of its own** (TD-25). `Hex64.decode` first validates exactly 16 characters of `[0-9a-f]` with a plain loop (no regex, no engine error) and only then calls `hex_decode` and `decode_s64`, because `hex_decode` alone accepts uppercase (probe 18) and reports bad input by logging; `Hex64.encode` calls `resize(8)` before `encode_s64` (probe 17). `campaign_id` (128 bits) is an **opaque 32-character lowercase `[0-9a-f]` String that is never converted to an int**; the local helper `CampaignId.is_valid(s)` applies the same exact-width, lowercase pre-check by loop. `registry_epoch` is compared as a string and never decoded. **Never `String.hex_to_int`** (probed: it saturates to `INT64_MAX` with an error on 16 `f`s). A `world_seed` or hash with the top bit set therefore reads as a negative GDScript `int`; that is correct, not a bug, and every consumer compares as `int`. Header numbers that stay numbers (`format_version`, `schema_version`, `generation`, lengths, offsets, counts, `hash_algo`, `codec`, `tick_rate`, `restore_epoch`) arrive as `float` from the parser and must be integral and **strictly below 2^53** before conversion; a value of 2^53 or more is refused (probed: `9007199254740993` parses to `9007199254740992.0`, so the first ambiguous value is exactly 2^53, which the strict bound catches). The header text becomes a `String` through `get_string_from_utf8` only after the trailer passed, and is parsed with `JSON.new().parse(text)`, whose returned `Error` is checked; invalid UTF-8 behind a passing trailer is a tamper case that may log an engine `ERROR` (**UNVERIFIED**) and is accepted only in the re-hashed fuzz configuration, like the `bytes_to_var` case of § 1.2.
- **Payload (binary).** `var_to_bytes` carries `int` at full 64-bit width exactly (probed with 2^53+1 and `PackedInt64Array`). The binary container therefore **accepts native `int64` in block payloads**; the "two 32-bit halves or strings" convention of TR-section-006, TR-assembly-013 and TR-shipbody-007 came from the JSON constraint and is **legal but not required**. S-1 is restated as: no float ever stands in for an integer, and a field that may reach 2^53 must be declared `int64` in its owner's snapshot schema so that `dump-save` (and any future JSON export) renders it as a string. This relaxes TR-saveload-017 and TR-sanity-020's "values stay below 2^53" for payload fields; it keeps it for everything JSON can touch. A float where an `int` is expected is a restore `SHAPE`-class failure of the owner (the sim is integer-only); an owner may still accept an integral float when importing from a dev JSON fixture, not from a binary payload.

**1.4 The ring and the campaign directory.** `user://saves/<campaign_id>/` holds `campaign.json` (a rebuildable hint, never truth, SL-3), `gen_0.sav` to `gen_{N-1}.sav` with `N` = `AUTOSAVE_GENERATIONS` 3, transient `gen_<write_epoch>_<k>.tmp` and `gen_<k>.bak`, `gen_<k>.demoted`, `slot_epoch_a.bin` and `slot_epoch_b.bin` (§ 3.1), `profile.sav` with a permanent `profile.bak` (both reserved: created at the first PROFILE block, § 1.8), `campaign.lock`, and `quarantine/`. **Order is the header `generation` number, never file name, mtime or `T`** (TR-saveload-005). Positions are chosen by F-9. Two encodings the GDD left open (OQ-27) are decided here:

- **Quarantine reason is in the file name:** `quarantine/g<generation>_<REASON>_<k>.sav`, `REASON` in {`CORRUPT`, `RESTORE_FAILED`, `STALE_EPOCH`}. `gen_next` reads the generation from the name without opening the file (SL-19). No sidecar and no manifest entry: a manifest is a hint and a sidecar can be lost separately from the file.
- **Retiring a campaign** renames its directory to `user://saves_retired/<campaign_id>/`, out of the active location, never deleting; `delete_campaign` is the separate hold-to-confirm action. The retired directory keeps the same layout so a retired campaign is restorable by hand.

**1.5 The write protocol, with what the probes change.** The sequence is T-4 as written (`CAPTURING`, `WRITING_TMP`, `VERIFYING`, `SWAPPING_OUT`, `SWAPPING_IN`, `POST_VERIFY`, `MANIFEST`, `WRITTEN`/`FAILED`), run on the worker. What the probes settle:

- **Rename over an existing, unlocked target works on Windows (probed) and replaces the target's content, but it is probably not atomic there.** The replacement is probably remove-then-rename (probe 1 note, about 65%, **UNVERIFIED**); on Unix `rename(2)` is atomic. The generation swap therefore **never relies on rename-over**: it renames the position's old file to `.bak`, then renames `.tmp` to a now-absent name, so a rename onto an existing name never occurs on the generation path. The reason is the failure cases: a target held open by an antivirus or indexer fails with `ERR_FAILED` and leaves the target intact (probed with a READ-held proxy; a remove-then-rename would behave identically, because the remove fails on a handle opened without `FILE_SHARE_DELETE`), and the `.bak` step makes every partial state recoverable by T-6 (at least two verified generations exist during any swap, since `N` >= 2). Whether a crash-time replace is atomic on NTFS is **UNVERIFIED** (SAVE-WRK-1 b and i).
- **`slot_epoch` uses neither rename nor remove; `campaign.json` uses rename-over as an accepted non-atomic exposure.** The epoch lives in two alternating files, each overwritten in place only while it is the older one (§ 3.1), so there is never an instant at which no valid epoch file exists. `campaign.json` (temp, flush, close, rename over the live name, re-read) is a rebuildable hint (SL-3, TR-saveload-041): on Windows a kill between the remove and the rename leaves it absent, and it is rebuilt from the generation headers; a failed rename of a held target leaves the old file (probed). **This window is recorded as an accepted exposure and is never described as "old file intact" across a crash**; SAVE-WRK-1 b and i count the "target missing" outcomes.
- **All `ERR_FAILED` are alike.** `DirAccess` reports a sharing violation, a missing parent and a permission error with the same code (probed: 1). Retries are therefore `RENAME_RETRY_COUNT` 3, `RENAME_RETRY_DELAY_MS` 50 on the worker for any rename failure, and the failure class is "rename failed", not a guessed cause.
- **Every `store_*` and `flush` result is checked** (`store_*` return `bool` since 4.4, sourced). `flush()` followed by `close()` then a re-open and re-hash is the "verified" definition; it proves readability through the operating system's cache, **not durability** (**UNVERIFIED**: whether `flush` implies an fsync; SAVE-WRK-1 c). The ring and T-6 recovery are the answer to power loss.
- **Temp names carry `write_epoch`** (`gen_<write_epoch>_<k>.tmp`, SL-10): an abandoned job's temp file and a later job's can never be the same file.

**1.6 The worker: one `Thread` per job, polled, never joined while alive.**

- **Model.** One `Thread` per `WriteJob`, its handle held on a `RefCounted` `WriteJob` that also carries the status record, started with `thread.start(WriteWorker.run.bind(block_bytes, header_template, paths, ints))` (the typed bound form of a static function, not the stringly `Callable(WriteWorker, "run")`). **`Thread.start` returns an `Error`; anything other than `OK` (for example `ERR_CANT_CREATE` when the OS refuses a thread) ends the job at once as `SL_WRITE_WORKER_DIED`**, with no worker and no `.tmp`. **`WorkerThreadPool` is rejected**: it offers no timed wait and its tasks cannot be abandoned individually (training knowledge; **UNVERIFIED** against 4.7, ADR-0010 may confirm). The Save/Load module is the **one** place `Thread` is legal (ADR-0010 IO-02, `src/save/` only).
- **Ownership transfer, not copy-on-write (engine review E1).** Packed arrays, Arrays and Dictionaries are reference-shared across threads in GDScript (probe 16); the engine enforces no immutability, so this ADR does. (1) At hand-off the main thread **holds no alias** to any handed-over object: a hot copy, a `SaveInfo`, a retry buffer or the `ControlOutcome` payload each count as an alias. A buffer the main thread must keep is handed over as `.duplicate()` (packed array) or `.duplicate(true)` (Array, Dictionary) instead. (2) The main thread never appends to, resizes or reuses a handed-over object afterwards. (3) The worker **never mutates, appends to or resizes an argument**; it builds new arrays for everything it produces. (4) The handed-over `Array[PackedByteArray]` and header template may be marked `make_read_only()` as a convenience; it is shallow (probe 14) and covers the top-level container only, so rules (1) and (2) carry the weight. A unit test hands a buffer off, mutates a retained alias and asserts the worker output is unchanged; it fails if an alias is kept without `.duplicate()`. The probe that "the caller's array is unchanged" shows only that the worker did not mutate it.
- **Status record.** `{state, write_epoch, generation, position, result_code, finish_or_abort, quit_requested}` guarded by one `Mutex`; the worker writes `state` at each T-4 stage and reads `quit_requested` between stages (it starts no new stage once set and leaves the `.tmp` to T-6); the main thread reads the record and writes only `finish_or_abort` (SL-10, `DOWNED` entry) and `quit_requested`. The worker never calls `call_deferred` (SIM-12), never touches a `Node`, never calls back (probed: no callback needed). The worker receives **only pre-globalised absolute filesystem paths**: `ProjectSettings.globalize_path` runs on the main thread, and the worker never resolves `user://` itself, so it touches no engine singleton for path lookup.
- **Polling.** `SaveHost._process` calls `SaveService.poll_frame()` once per frame. `SaveHost` is the thin `Node` of `src/game/save_host.gd` (L4, ADR-0010 § 1.1, beside `KernelHost`) with `process_mode = PROCESS_MODE_ALWAYS` and `process_priority = ProcessPriority.HOST_SERVICE` (-40: after `TICK_DRIVER` -50, before `PRESENTATION` 0; the one constant, named and valued in ADR-0001, TD-04); it is a known non-presentation node in the KRN-05 boot walk, holds no `FileAccess` and no `Thread`, and owns nothing but the injected `SaveService`. `SaveService`, `WriteJob`, `WriteWorker`, `PreCheck`, `SaveCodec`, `SlotEpoch`, `RegistryView` and `BuildConstants` are `RefCounted` under `src/save/` with no tree access, so ADR-0010 SIM-01 keeps its no-waiver status. **There is no separate tick-boundary poll:** the frame poll after the driver is the only observation point. A `request_snapshot` is served at the next boundary service, before any tick, so state read at the end of frame N is exactly the state captured in frame N+1 (OQ-F closed). That the frame poll fires in `PAUSED` and `LOADING` is **UNVERIFIED** (needs a scene tree; SAVE-WRK-1 e).
- **Reaping and lifetime.** Each poll calls `wait_to_finish()` **only** on a job whose thread reports `not is_alive()` (probed: returns at once with the callable's value). A dead thread with no terminal `WRITTEN`/`FAILED` status is `SL_WRITE_WORKER_DIED`: `save_status` `FAILED`, `fail_n` + 1, the ring position released, the `.tmp` left to T-6. **A live thread is never joined**: `Thread.wait_to_finish` and the pool wait take no timeout (training knowledge), so a join at the `DEAD` boundary could hang the frame on a hung write. **Every `WriteJob` stays referenced from `SaveService.jobs` until it is reaped or the process exits**, including an abandoned job: a `Thread` object freed while its thread still runs logs the same `~Thread` warning as the quit probe and detaches the worker from any owner, orphaning its buffers, so dropping a live job on abandonment or on `SaveService` teardown is forbidden and a freed live job is a fault in debug builds.
- **Abandonment** is SL-10 as written (`write_epoch` bump, position claimed, `MAX_LIVE_ABANDONED_JOBS` 2, `WRITE_JOB_TIMEOUT_MS` 30 000, `DEATH_STUB_WRITE_WAIT_MS` 5 000, all measured on the injected `Clock` port). A job that lands a generation after being abandoned is moved to `quarantine/` as `STALE_EPOCH`.
- **Quit during a write: "bounded join" is bounded polling.** Process exit does not wait on a busy worker (probed: an 8 s sleeping worker did not delay exit past 0.68 s; the engine prints a `~Thread` WARNING and an ObjectDB leak report, which are expected and are ADR-0010's to allow-list, § 8.6). Save & Quit therefore **polls** the `QUIT` job under `SAVE_QUIT_TIMEOUT_MS` 3 000 on the injected `Clock` and calls `request_shutdown` on `WRITTEN`; on timeout it does not abandon (a late completion is simply a `QUIT` generation, SL-6), reports `FAILED`, and the Chart Table offers the hold-to-confirm "quit without saving". An abandoned worker still running at exit is left to the operating system and its `.tmp` handled by T-6 on the next open. A worker blocked in a syscall rather than a sleep, or one that touches freed singletons while the engine tears down at exit, is **UNVERIFIED** (SAVE-WRK-1 d tests a worker mid-`store_buffer` and mid-`rename` at quit, on dev and release builds; the `quit_requested` check between stages shortens the tail).
- **Window close and OS quit (TR-saveload-039: Partial here; the quit transition is ADR-0003's `SHUTTING_DOWN` state, entered only through ADR-0002's `request_shutdown`; ADR-0030 owns the UI).** The window X button, Alt+F4 and OS shutdown deliver `NOTIFICATION_WM_CLOSE_REQUEST` (and, on mobile, `NOTIFICATION_WM_GO_BACK_REQUEST`), and `SceneTree` auto-accepts it by default and quits at once, which would cut a write in flight. `SaveHost` therefore sets `get_tree().auto_accept_quit = false` on entering the tree and forwards both notifications to `SaveService.on_close_request()`, which routes by kernel state as TR-saveload-039 lists: `RUNNING` and `PAUSED` write a `QUIT` generation then quit, `LOADING` defers, `SAVING` settles then dedupes or writes, `DOWNED`, `FAULTED` and boot screens write nothing, and a failed or timed-out write holds the close (the quit-without-fresh-save flow above). It **never blocks**: if a `QUIT` or `AUTO` write is in flight it polls under `SAVE_QUIT_TIMEOUT_MS`, then calls `ControlHandle.request_shutdown()`. **`request_shutdown` is the only place `get_tree().quit()` is reached.** A close request that arrives during the epoch wait of § 3.3 is held until `EPOCH_DURABLE` or the 2a path completes. A test drives the close-request path with an injected stalled worker.

**1.7 Single-instance lock (corrects SL-10), Windows-only best effort.** The GDD's `campaign.lock` "created with an exclusive open" is **not implementable with `FileAccess`**: a second WRITE-open of the same path succeeds (probed; WRITE mode truncates per the documented flag semantics). What does work on Windows (probed): a file held open makes `rename_absolute` and `remove_absolute` of it fail with `ERR_FAILED`, for READ and WRITE handles alike. The lock is therefore: the process that opens a campaign keeps a `FileAccess` handle on `campaign.lock` open (write mode, containing its process id, diagnostic only) for the campaign's lifetime; a second process tests ownership by renaming the file to `campaign.lock.probe` and back; a failure means "held", and it opens the campaign **READ_ONLY** (SL-10, AC-SL-147). `DirAccess` reports a missing source and a held target with the same `ERR_FAILED` (probed), so the probe **runs only when `campaign.lock` exists**; a missing file means "not held": the process creates it and holds the handle. A READ handle held for the campaign's lifetime suffices (probed: READ-held targets also fail rename and remove), which avoids depending on WRITE-mode truncation. A crashed holder releases its handle with the process, so there is no stale-lock case and no process-id liveness check is needed (`OS.is_process_running` is probed true for the own id, but whether it answers for a foreign non-child process is **UNVERIFIED** and is not used). **Handle lifetime:** a GDScript `FileAccess` closes when its last reference goes away (scope exit, reassignment, `null`, freeing the owner), so the handle is a **member of `SaveService`** (never a local), is never reassigned or nulled until the campaign closes, and a debug assertion checks `FileAccess.is_open()` in each frame poll. **Accepted exposure:** when the lock is not held the probe moves the file aside for an instant, and a third process starting at that moment sees "missing = not held" and also acquires it; for a single-instance guard this is acceptable and recorded, not engineered around. On Linux and the Deck, rename of an open file is expected to succeed (**UNVERIFIED**, SAVE-WRK-1 g), so the lock gives no protection there; Steam launches a single instance by default. The whole mechanism is best effort and deferrable to Alpha (OQ-D); if deferred, `campaign.lock` is not created at MVP and AC-SL-147 moves with it.

**1.8 The PROFILE split (reserved at MVP).** SL-9 as written: one kernel snapshot, split by `persist_scope` at write time; WORLD blocks to the generation, PROFILE blocks to `profile.sav` (same container, `file_kind` `PROFILE`, no `state_hash`, no `restore_epoch`), same atomic procedure with a **ring of one plus a permanent `.bak`** (the swap keeps the `.bak` instead of deleting it). **Zero PROFILE blocks ship at MVP, so the PROFILE file mechanism (ring of one, `.bak`, change-detection trigger, `PROFILE_MIN_WRITE_GAP_TICKS` 300) is specified here but is built and tested with the first PROFILE block, not before Alpha;** `file_kind` and `persist_scope` stay reserved in the format so that nothing needs migrating later. An in-session restore passes **only WORLD blocks** to `request_restore`, so PROFILE blocks are never rolled back (TR-cmd-017, TR-saveload-019); a cold open loads each scope whole from its own file. When built, a profile write is triggered when the **uncached `block_state_hash`es the kernel returns in the snapshot outcome** (TD-05) differ from those recorded at the last PROFILE write (never ADR-0005's cached hashes, TD-24), on `QUIT`, and at most every `PROFILE_MIN_WRITE_GAP_TICKS`. `scope` (SHARED/PER_PLAYER) and `persist_scope` (WORLD/PROFILE) are orthogonal: `suit.state`, `sanity.state` and `sanity.ledger` are PER_PLAYER x WORLD and roll back with the death stub (TR-suit-029, TR-webmap-030). **Display settings are not PROFILE state** (host-local Chart Table state, CT-19); see the scope note in the Ordering Note.

**1.9 Capture cost and the snapshot hitch (OQ-14).** The kernel owns capture (`SNAPSHOT_BUDGET_MS` 16.7, a ceiling, kernel GDD), including the **uncached** `state_hash` and per-block `block_state_hash`/`enc_len` computed in `SAVING` (ADR-0005 §§ 4.7, 5.4). Save/Load adds on the main thread only `var_to_bytes` per block (`t_file_encode`, log threshold `SAVE_ENCODE_BUDGET_MS` 4) and the hand-off (`t_handoff`, at most `WRITE_HANDOFF_MAX_FRACTION` 0.05 of the budget); SHA-256 of payloads, the header and the trailer are worker work (T-4, F-5). **Ruling (proposed, for the kernel owner to confirm): keep `SAVING` atomic, accept one over-budget frame per autosave, document it, and let SAVE-WRK-1 f measure it.** Evidence, all synthetic and probed: encode of 860 KB of synthetic block data 1.9 ms, deep copy 2.0 ms, SHA-256 of 300 KiB 0.7 ms, decode 3.5 ms; the MVP slice is 14 blocks and about 86 KiB to 300 KiB (SL-19), so the Save/Load-owned share of the hitch is of order 1 to 2 ms against the 4 ms threshold. The unmeasured share is the owners' real `snapshot()` implementations and the kernel's capture-time `H64` hash. A 32-block snapshot reaching 16.7 ms (TR-cmd-032) therefore exceeds the 14.9 ms desktop frame target for **one frame per autosave** and no more; the autosave gate already keeps that frame away from tells (SL-5). The synthetic half is measured by SAVE-WRK-1-ACCEPT f; the real-owner half by SAVE-WRK-1-SLICE on RM-DESKTOP and RM-DECK, which also decides which rung is needed. **Mitigation rungs, in order, only if the measurement shows the frame is visible (P99 above `16.7 - P99(baseline CPU frame work)`, the formula already in `SAVE_HITCH_BUDGET_MS`):** (1) **Deferred, off by default.** The kernel may skip `snapshot()` for a block whose ADR-0005 cache entry is valid by touch serial (`entry_valid`) since the last capture, reusing the previous encoded bytes. Enabling it requires a technical-director ruling on the SAVE-WRK-1 measurement (ADR-0005 OQ-10) and a matching ADR-0005 § 5.4 amendment; it is a kernel/ADR-0005 decision, not Save/Load's, and there is **no dirty-key dependency** (ADR-0004 § 7: a dirty key cannot gate caching, quantised writes mark nothing). (2) Move `var_to_bytes` to the worker, which relaxes TR-saveload-007 from "only `PackedByteArray`s" to "plus one Save/Load-owned, never-again-touched deep copy" (OQ-53 a: `snapshot()` returns caller-owned data). (3) Split capture across frames, which the kernel's atomic-`SAVING` rule forbids today and needs a kernel GDD amendment. Rungs 2 and 3 are not decided here. **Type-walk cost (engine review E10):** the load-side walk is a GDScript loop, plausibly 0.3 to 1 microsecond per node per check (**UNVERIFIED**), so a typical 10 000 to 30 000 node save costs about 5 to 20 ms and the old 250 000-node bound could cost 100 ms or more; the walk therefore runs on the hot-copy worker when it can, `MAX_DECODE_NODES` is provisionally 100 000 (§ 1.2), and SAVE-WRK-1 f carries the target "walk at most 4 ms at 30 000 nodes". The death stub's single synchronous attempt (SL-11) is the case this protects.

**1.10 Pre-check, recovery and failure classes.** T-5 (the 23-step ordered pre-check), T-6 (crash recovery) and the failure classes of SL-11 stand as written. This ADR adds three things:

- **A newer catalogue is INCOMPATIBLE, not owner-failed.** After step 12 (`tick_rate`) and before step 13 (the block table): a header `catalogue_version` greater than the running build's is `SL_PRECHECK_CATALOGUE_NEWER`, class INCOMPATIBLE, stop, no quarantine ("made by a newer build"). Without it, a downgrade would surface as `GRAPH_RESTORE_UNKNOWN_DEF` or `SUIT_RESTORE_UNKNOWN_DEF`, an *owner-reported* failure that quarantines a good file after `QUARANTINE_AFTER_FAILURES` 2. A *lower or equal* version proceeds: owners resolve renamed defs through ADR-0007's alias path. `catalogue_hash` is diagnostic only and never gates a load.
- **The pre-check is a pure static function** `PreCheck.run(bytes: PackedByteArray, registry: RegistryView, build: BuildConstants) -> PreCheckResult`, no clock, no file handle, no `Node`, unit-tested over in-memory byte arrays (TR-saveload-014). `RegistryView` is a plain-data snapshot of `(block_id, supported_versions, persist_scope, persist, added_in_format)` triples that Save/Load builds once after the registry freeze; `RegistryView` and `BuildConstants` live in `src/save/` (built by Save/Load from the frozen registry and the build, no import edge to `data`).
- **Reproduction mismatch stays a diagnostic.** The kernel's K-4 verdict arrives in `ControlOutcome` (ADR-0002 § 6); `SL_VERIFY_NOT_REPRODUCED` is never a fallback reason (TR-saveload-015).

**1.11 Fault domain 1 and the closed reason sets.** `src/save/save_load_faults.gd` (`class_name SaveLoadFaults extends RefCounted`, `const DOMAIN_ID: int = 1`, packed codes `(DOMAIN_ID << 16) | n`, and `const NAMES: Array[StringName] = [&"", &"PRECHECK_FILE_SHA_MISMATCH", ...]` indexed by the local code with index 0 = `&""`, the shape of ADR-0003's `GraphFaults.NAMES`) holds the closed sets `SL_PRECHECK_*`, `SL_WRITE_*`, `SL_LOAD_*`, `SL_VERIFY_*`, `SL_EPOCH_*`, `SL_QUIT_*`, `SL_NEW_GAME_*` and `SL_BOOT_*`, and Save/Load calls `register_fault_domain(1, &"save_load", NAMES)` in `BOOTING` through the BOOTING-only registrar facet that ADR-0003 gives a host service (limited to `register_fault_domain`; no block or hook registration), so diagnostics print `save_load.PRECHECK_FILE_SHA_MISMATCH`. **None of these faults the kernel**: a bad file, a failed write and a refused quit are values and diagnostics, and the kernel's own codes (`CAPTURE_ERROR` 7, `RESTORE_EPOCH_RANGE` 6, `RESTORE_UNKNOWN_BLOCK` 4, `TICK_RATE_MISMATCH` 5, all domain 0) are the unreachable backstops behind Save/Load's pre-check. Registering a domain is neither a block nor a hook, so TR-saveload-018 holds. Knob range and invariant failures (`SL_BOOT_KNOB_RANGE`, `SL_BOOT_KNOB_INVARIANT`) are **domain 2** content boot errors raised by the ADR-0007 `ScalarTable` machinery (TR-saveload-024 is ADR-0007's); only the cross-check of § 2.3, which needs the live registry, raises domain 1 `SL_BOOT_*`.

**1.12 The host API and what Save/Load may observe.** SL-21 as written: `new_game(world_seed)`, `continue_campaign()`, `save_and_quit()`, `cancel_held_close()`, read-only `campaign_info()`, `list_saves()`, `retire_campaign`, `delete_campaign`, and the host-local reads `save_status`, `fail_escalated`, `SaveInfo`, `restore_reason`, `restore_epoch` (diagnostic), `quit_held`, `quit_write_active`. No `save_now`, no `load(generation)` outside dev builds, no command registered (TR-saveload-023). Save/Load is a **polling control-plane caller, not a subscriber** (SL-13; TD-09): it holds a `ControlHandle` and a `save_load` facet of read views, subscribes to nothing and gets no end-of-tick callback and no sixth subscriber class. `SaveService.poll_frame()` (called by `SaveHost`, § 1.6) compares **monotonic counters** with the last values it saw; counters are chosen over level flags or `last_*_T` so that several events inside one catch-up frame are not lost. **The observation set (Save/Load's decision, owned here):** `kernel.clock`, `controller.state.loco_state` and `carry_ref` and `suit` `carried_id` (the SL-5 gate rows; TR-suit-035), `suit` `vitals_state`, `graph` failures, `attention.view`, Assembly's `ragged_breach_open()` and `last_shape_change_T()`, Interaction's `last_salvage_T()`, and the **conditional `web.state` read-view members `pod_arrived_seq: int` and `berthed_seq: int`**, recorded as a requirement on the Web Map ADR (Save/Load's half of TR-webmap-023). Until the Web Map ADR supplies them, the POD_ARRIVED and BERTHED triggers are absent and never fire (GDD rule: an event whose owner read is absent never fires). The last-seen copies are host-local and are re-read after a load, so a load never fires an autosave. ADR-0004 OQ-3 is closed from this side: Save/Load polls owner read views, there is no subscription class. Save/Load never reads a `PERCEPTION_OUT` view and never writes a block. It registers one `ControlHandle.set_outcome_handler` method `Callable` with the signature `(outcome: ControlOutcome, ctx: NotifyContext) -> CompletionToken` that returns a token on every path, and uses it for the snapshot outcome (payload plus the hash data of § 1.1) and the K-4 verdict; `request_snapshot()` itself returns `void`.

### 2. Versioning and migration

**2.1 Two levels, as SL-14.** `format_version` (container) is migrated by Save/Load; `schema_version` (per block) is migrated only by the owner inside `restore(data, stored_version, ctx)` as a chain of registered pure functions `(old Dictionary) -> new Dictionary`. Save/Load never rewrites block data. `min_reader_version` equals `format_version` on every write in the MVP. A migrated payload is **not written back** to the old file; the next autosave writes the new shape, so a downgrade-then-upgrade cannot half-migrate a file.

**2.2 The block contract in ADR-0003 terms.** Reconciling SL-15 with the registered owner-callable contract (ADR-0003 § 1, registry `owner_callable_contract`): a persisted block registers `snapshot`, `restore`, `default_state` and `post_restore` as `Callable`s each returning `ctx.complete()`, with `supported_versions`, `persist_scope` and `restore_after` in its `BlockDescriptor`.

- `snapshot(ctx)` calls `ctx.put(payload: Dictionary)`: a deep copy (no aliasing of live state, so the encode may later leave the main thread; packed arrays in the payload are duplicates, never live references, ADR-0003 snapshot contract), plain data per § 1.2, rows sorted by id, no derived caches, no object references, transient fields normalised (TR-pc-020).
- `restore(data: Dictionary, stored_version: int, ctx)` is **two-phase: decode and validate into scratch, then copy the contents into the existing block object**. This is the single wording of the rule; "whole-block replace" and "swaps whole tables from scratch" in owner GDDs mean *replace the block's contents*, never the object (registry `block_as_resource_or_node`; ADR-0003 § 2: read-view facades are long-lived).
- **Failure is reported through `ctx.fault(<OWNER>_RESTORE_*)`** with the owner's domain code and a named detail, never by return value and never by clamping; the kernel fires `load_failed` and Save/Load maps it to the `RESTORE_FAILED` class of SL-11. Owner GDDs that describe `(ok, reason, detail)` mean this (ADR-0003 sync, not this ADR's to change).
- `post_restore(ctx)` rebuilds derived caches and cross-block verification; `default_state(ctx)` fills a block missing from an older file whose `added_in_format` exceeds the file's `format_version`.
- A restore is idempotent: `snapshot(restore(snapshot()))` is canonical-byte identical except for the closed `REBASE_BLOCKS` list (SL-12), and the Graph's, Body's and Controller's tests prove it.

**2.3 Block versions are data, cross-checked at boot.** `added_in_format`, `RETIRED_BLOCKS` and the mandatory flag live in one committed file `assets/data/saveload/block_versions.json` (loaded by ADR-0007's pipeline in the composition root as a closed-schema table and injected, with the Save/Load `ScalarTable`, into `SaveService.setup()` as plain data, so `save` needs no import edge to `data`; `save` may type variables with ADR-0007's published value types, TD-27), not in `BlockDescriptor`, so ADR-0003's descriptor field list is unchanged. After the registry freeze, the composition root runs `SaveBootCheck.verify(block_versions, registry_view)`: a mandatory-derivation mismatch, a registered block that is also retired (`SL_BOOT_RETIRED_BUT_REGISTERED`), or a missing entry fails boot with a domain-1 `SL_BOOT_*` code and the root never starts the kernel. A persisted WORLD block is **mandatory iff its `added_in_format` is at most the file's `format_version`**; the MVP set in SL-25 is the *result* of that rule, not a hand-kept list.

**2.4 `registry_epoch` and `catalogue_version`.** `registry_epoch` (the header field that tells "the registry moved" from corruption) is the first 8 bytes of SHA-256 over the UTF-8 text of the sorted lines `block_id:schema_version:added_in_format\n` for every persisted block, as lowercase hex. It uses `HashingContext` directly, **not** H64 or the canonical encoding, so it depends on neither ADR-0005 nor the kernel. A file whose `registry_epoch` differs from the running build's and fails a mandatory-set or schema step is INCOMPATIBLE-dev: never CORRUPT, never quarantined (SL-11, T-5 steps 18 and 21). `catalogue_version` is the Item DB's single integer offered by ADR-0007 § 3.4; it is written in the header as an `int`, and its only gating use is the newer-than-build refusal of § 1.10.

**2.5 `hash_algo` and `codec`.** `hash_algo` 2 names H64 (the first 8 bytes of SHA-256 via `HashingContext`, read little-endian, ratified by the GDD, owned by ADR-0005); 0 and 1 are reserved, never written (they are `hash_algo` ids, not hash values: no `H64` value is reserved as a sentinel, ADR-0005). An unsupported `hash_algo` skips the reproduction compare (`SL_VERIFY_ALGO_SKIPPED`, REBASED cause 4) so a kernel hash change is never a save-breaking event. `codec` 0 only.

**2.6 Policy and fixtures (SL-14, unchanged).** The migration machinery exists from format 1. Two goldens: `tests/fixtures/saves/v1-standin/` (regenerated freely until the registry settles) and `tests/fixtures/saves/v1/` (generated from the real registry at the first outside build, immutable, with a CI schema-drift fingerprint: the `registry_epoch` of the committed shapes may change only together with a `schema_version` or `format_version` bump). The obligation to migrate begins with the first build given to anyone outside the project; before it, a mismatched development save is refused as "made by an incompatible development build". This is the same moment ADR-0007's id ledgers flip to `SHIPPED`; one project-level decision flips both.

### 3. The restore epoch

**3.1 Ownership and storage.** Save/Load owns `restore_epoch`, an unsigned 32-bit integer (an `int` in `[0, 2^32 - 1]`) starting at 0 at `new_game` (SL-18); it has exactly one owner and registry entry. It lives in a per-slot **pair of side files**, `user://saves/<campaign_id>/slot_epoch_a.bin` and `slot_epoch_b.bin`, each **12 bytes: the epoch as `u32` LE, a sequence number `seq` as `u32` LE, then the CRC32 of those 8 bytes as `u32` LE** (the GDD / TR-saveload-020 format of `u32` plus CRC32 gains the `seq` field; GDD sync). The reader takes the valid file (size 12, CRC matches) with the higher `seq`; the writer always overwrites the **older** file in place (an invalid file, or the lower `seq`) with `seq = max + 1`, flushes, closes, re-reads and checks the CRC (that re-read is the `EPOCH_DURABLE` report). **No rename and no remove is involved**, so there is never an instant with no valid epoch file: a kill mid-write corrupts only the file being written and the other still holds the previous durable value. (A single file replaced by rename-over would, on Windows, probably be remove-then-rename, § 1.5, open a window in which the file is absent, and let the rebuild rule of § 3.4 yield `max(header copy) + 1`, which can be lower than an epoch already advanced, for example after two deaths with no autosave between them, replaying one set of threat draws; engine review E2.) `seq` saturates at 2^32 - 1, unreachable in practice because the epoch saturates first. `SlotEpoch.encode` calls `resize(12)` before any `encode_u32` (probe 17). **CRC32 is hand-rolled** (polynomial `0xEDB88320`, init and final XOR `0xFFFFFFFF`, bitwise, over 8 bytes): `PackedByteArray` has no `crc32` (probed), the scripted loop matched the standard check vector, its cost is of order microseconds, and a truncated hash was rejected as a gratuitous change to the GDD format. The vector `crc32("123456789") == 0xCBF43926` is a unit test. The files are in no generation, so no generation's bytes, trailer, `state_hash` or any key derived from them changes after `VERIFYING`; this is what makes SL-12's REBASED baseline key stable (R14). Each WORLD generation's header carries a **read-only write-time copy** (`restore_epoch`, an int below 2^32) used only by the rebuild rule of § 3.4; it is never rewritten.

**3.2 When it advances (R13, unchanged).** A death-stub restore and a `FAULT_RECOVERY` always advance it. A Continue (`LOAD_GAME`) advances it unless the generation it restores is a `QUIT` generation that is the newest non-demoted verified generation: that Continue **carries the epoch unchanged and writes nothing**, so Save & Quit then Continue replays the threat draws an uninterrupted run would meet and quit buys nothing. An advance is `restore_epoch := min(2^32 - 1, max(e_mem, e_slot) + 1)`, saturating and logging at the top; a step-back, a demotion, a quarantine or a lost manifest cannot lower it. A stub that finds nothing loadable restores nothing and does not advance it. The Graph's physical failures and every persisted counter never read the epoch.

**3.3 Durable before the restore is requested (R14, with the polling decided).** After selection, pre-check and staging, Save/Load computes the new value and hands the `slot_epoch` write (the older of the two files, § 3.1) to the worker **as its own job**, never queued behind a generation write or an abandoned job, and polls it once per frame from `poll_frame` (never blocking, never joined). Only on `EPOCH_DURABLE` does it call `ControlHandle.request_restore(payload, restore_epoch, expected_state_hash, has_expected_hash)`, so the kernel's `LOADING` holds no wait on Save/Load I/O and stays atomic within one boundary service. On the death stub the kernel is `RUNNING` from the `DEAD` boundary to that call (at most `RESTORE_EPOCH_WRITE_MAX_MS` 500 on the injected `Clock`, 30 frames); the seat stays `DEAD`, the hard gate is closed, and a `restore_pending` latch refuses **Save/Load's own capture requests** and answers a further restore trigger with `SL_LOAD_REENTRANT`. **Save/Load cannot refuse a pause:** pause requests come from PauseGate's own `ControlHandle` (ADR-0002). If the player pauses during the wait, the restore would be requested from `PAUSED`; this ADR therefore requires that either PauseGate or the Chart Table suppresses pause while a seat is `DEAD` (ADR-0030), or that ADR-0003's transition table lists `request_restore` from `PAUSED` as well as `RUNNING` (OQ-J, owed by ADR-0003 or ADR-0030). A test pauses during the epoch wait and asserts the restore still reaches `LOADING` exactly once. The Player Controller's DEAD hand-off (TR-pc-022) is honoured only after `EPOCH_DURABLE`.

**3.4 Failure and recovery.**
- **Write fails or times out (2a):** Save/Load still calls `request_restore` with the advanced value held in memory, logs `SL_EPOCH_NOT_DURABLE`, sets `save_status` `FAILED`, and the worker retries the file with the next write job and after every later `WRITTEN` generation while memory is ahead of disk. A kill before then may replay that epoch once (OQ-25, an accepted and listed exposure: the device is failing and no write can fix that).
- **Both epoch files missing or invalid (2b):** (one valid file is a normal read, not a failure) the value reads as `max(newest verified generation's header copy, 0) + 1`, logs `SL_EPOCH_FILE_REBUILT`, and is rewritten by the worker into the older slot. Deleting the side files by hand therefore re-keys the next stretch once, a tampering exposure of the same class as editing any save. Because the pair removes the remove-then-rename window, a missing-file state is reachable only by tampering, a first-ever write interrupted at creation, or media loss.

**3.5 Reaching the sim.** `request_restore` and `request_new_game(world_seed, restore_epoch = 0)` pass the epoch as an argument; the kernel range-checks it (`RESTORE_EPOCH_RANGE`, domain 0 code 6) and exposes it read-only, sim-visible and **non-persisted, non-hashed** in the `kernel.clock` read view as `(T, world_seed, restore_epoch)` before the first `restore()`; it is read only inside `RngFacet.draw_epoch` (ADR-0003, TD-07). The one derivation, `counter_eff = rng_counter + RESTORE_KEY_STRIDE * restore_epoch`, belongs to the kernel and ADR-0005 (`rng_derive_epoch`); Attention and Horror call it and never store the epoch (TR-attention-024, TR-horror-017). Determinism is defined given the pair: the same (save bytes, `restore_epoch`) replays identically, and tests pin the epoch. The phrase "excluded from the snapshot header" (TR-cmd-018) means *the kernel snapshot payload and every `H64`*: the **container** header carries the recovery copy of § 3.1, which is covered by the file trailer (file integrity) and by no state hash.

**3.6 Staging and hot copy.** Candidate selection (SL-8), the death-stub's one synchronous attempt per candidate and the newest and preceding **hot decoded copies** (SL-11) stand as written; the hot copies are held by Save/Load and are never handed to a worker (a retained alias of a handed-over buffer is forbidden, § 1.6). The payload handed to `request_restore` is built in memory by Save/Load (not decoded from one blob): `Dictionary` of `StringName block_id -> {&"schema_version": int, &"data": Dictionary}`, with `kernel.clock` included, `data` dictionaries marked read-only as a shallow convenience (`Dictionary.make_read_only()` is **shallow**, probe 14, so owners copy what they keep, OQ-53; a deep read-only snapshot, where wanted, is built by the owner from `duplicate(true)` at capture). The expected hash is passed as **two typed arguments**: `expected_state_hash: int` (the header `state_hash`) and `has_expected_hash: bool`, `false` when the file legitimately carries none (a release-build file that predates K-4: verdict `NONE`). No `null` and no `Variant` (ADR-0002, TD-05; OQ-B closed): `Variant` is banned in typed interfaces, passing `null` to an `int` parameter is a runtime error, and a legitimate `H64` of 0 exists, so no value is a sentinel.

### Implementation Guidelines

Mandates are stated as must / must never so `/create-control-manifest` can extract them.

**Container and codec**
- Save/Load **must** write every block payload as `var_to_bytes(dictionary)` and decode only with `bytes_to_var`; it **must never** call `var_to_bytes_with_objects` or `bytes_to_var_with_objects`, and **must never** use a `Resource`, `.tres`, `.res`, `ResourceLoader` or `load()` for a save, a snapshot or a profile.
- The type walk **must** reject `TYPE_OBJECT` (including `EncodedObjectAsID`), `StringName`, every vector, rect, `Color`, `Callable`, `Signal`, `RID`, `NodePath` and non-finite floats; it **must** run on the worker in `VERIFYING` over the bytes just written and after every load decode on the hot-copy worker when it can, else on the main thread (target: at most 4 ms at 30 000 nodes, SAVE-WRK-1 f).
- 64-bit header fields **must** be read with `Hex64.decode` (exact-width, lowercase `[0-9a-f]` pre-check by loop, then `hex_decode` and `decode_s64`; ADR-0005 § 4.2); code **must never** call `String.hex_to_int` or `int()`/`to_int()` on a 64-bit field, **must never** call `hex_decode` on unvalidated header text, and **must never** parse a 64-bit or hash value from a JSON number. Header integers **must** be integral and strictly below 2^53.
- The trailer SHA-256 **must** be checked before the layout-id byte is judged, and `header_len` **must** be range-checked before any allocation.
- The file size **must** be checked against `MAX_SAVE_BYTES` before the file is read.
- A typed collection **must** be built with `append()` or `Array.assign()`; code **must never** assign an untyped `Array` (for example a JSON result or a plain local) to a typed `Array[...]` return or parameter, which is a runtime type error. `HashingContext.update` **must never** be called with a zero-length chunk. Save/Load classes **must not** declare a `_to_string`, `_get`, `_get_property_list` or `_get_configuration_warnings` override without an explicit `return` on every path (the 4.7 typed-return rule).
- 64-bit values **must** go through ADR-0005's `Hex64.encode` / `Hex64.decode` (`src/shared/det/`); Save/Load **must never** define a second 64-bit codec. The 128-bit `campaign_id` **must** be an opaque 32-character lowercase `[0-9a-f]` String validated by a plain loop and **must never** be converted to an int. Any `encode_*` on a `PackedByteArray` **must** follow a `resize()` that allocates the bytes.
- Block data and the header **must never** contain a wall-clock value that the sim reads; `created_unix` and the time `SaveInfo` displays come from the injected `WallClock` port, are display metadata only, and **must never** be read by ordering (the generation number is the only order), a gate, a hash or the sim. Every millisecond timeout **must** read the injected `Clock` port (`FakeClock` in tests), never `Time.*`.

**Write path and threading**
- A write **must** go to `gen_<write_epoch>_<k>.tmp`, flush, close, re-open, re-hash and decode before any rename; **every `store_*`, `flush` and rename result must be checked**; an existing generation **must never** be overwritten in place, renamed onto, or deleted before its successor verified; nothing **must** be written while the kernel is `FAULTED`.
- Only the Save/Load module (`src/save/`, ADR-0010 IO-02) **may** create a `Thread`; it **must** create one per job and **must** check the `Error` returned by `Thread.start` (anything but `OK` ends the job as `SL_WRITE_WORKER_DIED`), **must** poll `is_alive()`, **must** call `wait_to_finish()` only on a thread that is not alive, **must** keep every `WriteJob` in `SaveService.jobs` until it is reaped or the process exits (a freed live job is a debug fault), and **must never** join a live thread, use `WorkerThreadPool`, call `call_deferred`/`set_deferred`/`call_thread_safe` (SIM-12), or hand the worker a `Node`, a block, a read view, a `Callable` that touches the scene tree, or any container of live state. The worker **must** receive only pre-globalised absolute paths (`ProjectSettings.globalize_path` on the main thread) and **must** check `quit_requested` between stages. The thread entry **must** be written `WriteWorker.run.bind(...)`, never `Callable(WriteWorker, "run")`.
- Packed arrays, Arrays and Dictionaries are reference-shared across threads: the main thread **must** hold no alias to a handed-over object, or **must** hand over `.duplicate()` (packed array) or `.duplicate(true)` (Array, Dictionary); it **must never** append to, resize, reuse or mutate a handed-over object afterwards; the worker **must never** mutate, append to or resize an argument and **must** build new arrays. A unit test hands off, mutates the retained alias and asserts the worker output is unchanged.
- A due `slot_epoch` write **must** be its own job on the **older** of the two alternating files (`slot_epoch_a.bin`, `slot_epoch_b.bin`; no rename, no remove), polled per frame; `request_restore` **must** be called only after `EPOCH_DURABLE`, or after the documented 2a failure path.
- Save & Quit **must** poll under `SAVE_QUIT_TIMEOUT_MS` on the injected `Clock` and **must never** block the frame or join the worker; millisecond timeouts **must never** enter a gate input or a sim decision. `SaveHost` **must** set `get_tree().auto_accept_quit = false` and route `NOTIFICATION_WM_CLOSE_REQUEST` (and `NOTIFICATION_WM_GO_BACK_REQUEST`) to `SaveService.on_close_request()`; `request_shutdown` **must** be the only place `get_tree().quit()` is reached.
- The campaign lock **must** be a held `FileAccess` handle tested by a rename probe, stored as a member of `SaveService` and never reassigned until the campaign closes; it **must never** rely on an exclusive `FileAccess.open`.

**Blocks**
- A persisted block **must** register `snapshot`, `restore`, `default_state` and `post_restore` as ADR-0003 Callables, **must** declare `supported_versions`, `persist_scope` and `restore_after`, **must** return plain data (§ 1.2), and **must** copy restored contents into its existing block object; it **must never** call Save/Load, hold a file path, or replace its block object in `restore`.
- A restore failure **must** be reported with `ctx.fault(<OWNER>_RESTORE_*)`; a restore **must never** clamp an out-of-range value.
- A field that may exceed 2^53 **must** be declared `int64` in the owner's snapshot schema; a float **must never** stand in for an integer.
- Save/Load **must never** register a state block, a step hook, a command type, or `save_now` / `load(generation)` outside a dev build.

**Versioning**
- Save/Load **must never** rewrite a block's data and **must never** write a migrated payload back to an old file.
- The pre-check **must** refuse `catalogue_version` above the build's as INCOMPATIBLE without quarantining; `catalogue_hash` **must never** gate a load.
- Block versions **must** be read from `assets/data/saveload/block_versions.json` and cross-checked against the live registry before the first request; a mismatch **must** stop boot.
- The frozen golden save **must** never be regenerated; a change to the committed shapes' `registry_epoch` **must** arrive with a `schema_version` or `format_version` bump.

**Epoch**
- `restore_epoch` **must** be stored only in `slot_epoch_a.bin` / `slot_epoch_b.bin` (and as the read-only header copy), **must** never be inside a snapshot payload, an `H64` input or a block, and **must** reach the sim only as the `request_restore` / `request_new_game` argument and the `kernel.clock` view.
- An epoch advance **must** use `min(2^32 - 1, max(e_mem, e_slot) + 1)`; code **must never** decrease the epoch for a step-back, demotion, quarantine or a lost manifest.
**Host, observation and ownership**
- `SaveHost` (`src/game/save_host.gd`) **must** be a thin `Node` at `ProcessPriority.HOST_SERVICE` holding only the injected `SaveService`; `SaveService` and every other Save/Load class **must** be a tree-free `RefCounted` in `src/save/`. Save/Load **must never** subscribe to a notification class, **must** observe only by polling monotonic counters and read views in `poll_frame`, and **must** re-read the last-seen counters after a load so a load never fires an autosave.
- Save/Load **must never** compute, re-derive or compare an `H64` itself and **must never** use a cached block hash on a decision path; the capture hashes come from the snapshot outcome. A persisted block **must** `put` a Dictionary.
- Settings (`DisplaySettings` and similar) **must never** be written into the save container or kernel state.

## Alternatives Considered

### Alternative 1: Scripted binary writer with canonical TLV for storage and hashing (one encoding)
- **Description**: Store each block in ADR-0005's canonical TLV form and hash those same stored bytes, so file bytes are canonical and `payload_sha256` could double as a block hash.
- **Pros**: One encoding; byte-identical files for identical state; no dependence on `var_to_bytes` layout stability across engine versions.
- **Cons**: A scripted encoder and decoder for every field type on the capture path (the encode is main-thread time); every owner must express its snapshot as TLV before ADR-0005 is even Accepted; decode needs a hand-written bounded parser (more attack surface than the native decoder); no gain for integrity, which the SHA-256 chain already provides.
- **Rejection Reason**: Cost on the critical frame and a hard dependency on a sibling ADR for the sake of a property (byte-identical files) nothing needs: state equality is `state_hash`. Recorded as the **rejected-for-now** path: moving storage to canonical TLV later is a `format_version` bump with a container migration, and the per-block `snapshot()` contract does not change.

### Alternative 2: `Resource` / `ResourceSaver` (`.tres` or `.res`) saves
- **Description**: Snapshot blocks as `Resource` subclasses and save with `ResourceSaver`.
- **Pros**: Built-in versioning hooks, editor inspection, typed fields.
- **Cons**: A `.tres` can embed scripts and external resources, so a loaded save is a code-execution path; blocks are `RefCounted` plain data by registry stance; no trailer, no per-block hash, no ring control; scene-tree-adjacent loading.
- **Rejection Reason**: Violates the save-file trust model (SL-2) and registry `block_as_resource_or_node`.

### Alternative 3: JSON for the whole file (or base64 payloads inside JSON)
- **Description**: One JSON document; blocks as nested JSON or base64 strings.
- **Pros**: Human-readable, trivially diffable, one parser.
- **Cons**: JSON numbers arrive as `float` (probed: 2^53+1 corrupts silently), so every 64-bit or hashed value needs a string convention in every block; packed arrays become number lists (slow, large); base64 inflates by a third and costs main-thread time; no cheap partial verification.
- **Rejection Reason**: Fights S-1 in every block. JSON stays in the header and the dev dump, where its readability pays and its number typing is handled by § 1.3.

### Alternative 4: Single save file overwritten in place (or one file plus one backup)
- **Description**: One `save.sav`, rewritten each time, or a current and a previous file.
- **Pros**: Simplest; least disk.
- **Cons**: One bad write (or a crash mid-write, or a locked file) loses the campaign; two files cannot support the RISKY and fairness step-backs (SL-8), which need an older verified generation after a demotion; `AUTOSAVE_GENERATIONS` 1 is forbidden by invariant I4.
- **Rejection Reason**: Fails the "never overwrites a good save" requirement and the death-loop rules.

### Alternative 5: `WorkerThreadPool` tasks for the writer
- **Description**: Submit the write as a pool task and `wait_for_task_completion` when needed.
- **Pros**: No thread lifetime management; engine-scheduled.
- **Cons**: No timed wait and no way to abandon one task individually (training knowledge, **UNVERIFIED** on 4.7), so a join at the `DEAD` boundary or at quit could hang on a stuck disk; pool saturation by other users is outside this module's control.
- **Rejection Reason**: The design requires a job that can be abandoned and a main thread that never blocks. One `Thread` per job, polled, gives exactly that (probed).

### Alternative 6: Join the worker with a timeout (loop on a semaphore or a timed wait)
- **Description**: `Thread.wait_to_finish` after a timed `Semaphore` wait, bounded at quit.
- **Pros**: Familiar blocking shape.
- **Cons**: A blocking wait on the main thread at quit or at `DEAD` is a frame hang on a hung write; `Semaphore` has no timed wait in GDScript (training knowledge, **UNVERIFIED**); polling achieves the same bound without the hang.
- **Rejection Reason**: Polling under a monotonic timeout (§ 1.6) is bounded and never blocks.

### Alternative 7: Exclusive-open lock file, or process-id liveness for the single-instance guard
- **Description**: Create `campaign.lock` with an exclusive open (the GDD's wording), or store a process id and test it with `OS.is_process_running`.
- **Pros**: Conventional.
- **Cons**: `FileAccess.open` is not exclusive (probed: two WRITE opens succeed); `is_process_running` answers for the own process but whether it answers for a foreign non-child process is **UNVERIFIED**; a stale pid after a crash can mislead.
- **Rejection Reason**: The held-handle plus rename probe uses behaviour that was probed and releases itself when the holder dies (§ 1.7).

### Alternative 8: Keep `restore_epoch` in the generation header and rewrite it on restore (the original R1)
- **Description**: Persist the epoch inside the generation file and rewrite that file's header when a restore advances it.
- **Pros**: No side file.
- **Cons**: Rewriting a verified file changes its trailer and every key derived from it (SL-12's REBASED baseline), races the write protocol, and loses the value when that generation is quarantined or the ring steps back.
- **Rejection Reason**: Superseded by R14: the per-slot side file survives step-backs and a lost manifest and leaves every generation immutable after `VERIFYING`.

### Alternative 9: Split capture across frames to meet the 14.9 ms target (OQ-14)
- **Description**: Capture a few blocks per frame so no frame exceeds budget.
- **Pros**: No over-budget frame.
- **Cons**: The captured blocks would be from different ticks unless the sim freezes, which is what `SAVING` already does; a multi-frame capture breaks the kernel's atomic-`SAVING` rule and the single-`T` guarantee that `state_hash` and the reproduction compare rest on.
- **Rejection Reason**: Contradicts the kernel contract; kept only as mitigation rung 3, behind a kernel amendment, if the spike shows the single frame is visible.
### Alternative 10: One `slot_epoch.bin` replaced by rename-over (the original R14 form)
- **Description**: Write `slot_epoch.tmp`, flush, close, rename over `slot_epoch.bin`, re-read with a valid CRC.
- **Pros**: One file; the same protocol as `campaign.json`; fewer states to test.
- **Cons**: On Windows the replacement is probably remove-then-rename (engine review E2, about 65%, **UNVERIFIED**; probes 1 and 2 cannot tell it from an atomic `MoveFileEx`), so a kill between the remove and the rename leaves no epoch file, and the rebuild rule (`max(header copy) + 1`) can then yield a value **lower** than the epoch already advanced, for example after two deaths with no autosave between them, replaying one set of threat draws. That reopens the reroll hole the epoch exists to close.
- **Rejection Reason**: Two alternating files, each carrying `seq` and a CRC and overwritten in place only while older (§ 3.1), need no rename and no remove, so a valid epoch always exists. The accepted-exposure route (keep rename-over, record the window) was rejected because the exposure is on the one value whose loss is a gameplay exploit.

### Alternative 11: `SaveHost` as a `Node` inside `src/save/`
- **Description**: Put the per-frame poll and the close-request handler in a `Node` next to the service, in the module that owns the `Thread`.
- **Pros**: One directory; no separate host file.
- **Cons**: ADR-0010 § 4.1 bans `Node` and `_process` in `src/save/` (SIM-01, no waiver), and the `Thread` allowance is scoped to that same directory, so a `Node` there would also be a node that can reach the thread. There is also no control-plane end-of-tick callback to poll from (SL-17 registers no hook).
- **Rejection Reason**: `SaveHost` is a thin L4 `Node` in `src/game/` beside `KernelHost`, at `ProcessPriority.HOST_SERVICE`, and the service stays `RefCounted` and tree-free (TD-10).

## Consequences

### Positive
- A bad write, a locked target, a kill at any step or a corrupt newest file costs at most one interval; the ring and T-6 recovery make every partial state recoverable by rule, and the only file ever replaced by rename-over is `campaign.json`, which is rebuildable, and the epoch pair is overwritten in place one file at a time.
- One container and one payload form for WORLD and PROFILE: one decode path, one type walk, one fuzz target.
- 64-bit values are exact in the binary payload with no per-block convention, and the header's hex rule is mechanical and tested.
- The probe findings (objects slip through the encoder; `FileAccess` is not exclusive; `hex_to_int` saturates) are turned into mandatory checks before any code exists.
- The epoch survives kill, step-back and a lost manifest, is durable before the restore that uses it, and changes no generation file; quit buys no reroll.
- The main thread never blocks on I/O and never joins a live thread; quit is bounded by polling.

### Negative
- The type walk and the write-side decode are load-bearing, not belt-and-braces; a gap in either lets an object reach disk. Cost: a walk over up to `MAX_DECODE_NODES` (provisionally 100 000) nodes at load (about 5 to 20 ms for a typical 10 000 to 30 000 node save and 10 to 30 ms for a Graph-sized payload; **UNVERIFIED**, target at most 4 ms at 30 000 nodes, SAVE-WRK-1 f; on the hot-copy worker when possible).
- Stored bytes are not canonical, so byte-comparing two saves proves nothing; tests must compare `state_hash`.
- One over-budget frame per autosave is accepted (§ 1.9) pending the spike.
- Immutability across the thread boundary is a discipline, not an engine guarantee: packed arrays, Arrays and Dictionaries are reference-shared (probe 16), so the alias rule of § 1.6 and its unit test are load-bearing.
- `campaign.json` still uses rename-over, which on Windows is probably not atomic: a kill in the window leaves it absent until it is rebuilt from the generation headers (accepted exposure, § 1.5).
- The PROFILE file is specified but unbuilt at MVP; the first PROFILE block carries its construction and test cost.
- The lock protects only on Windows as probed; Linux and the Deck rely on single-instance launch.
- A hand-rolled CRC32 and a hand-rolled single-instance lock are code the project owns and must test.
- `var_to_bytes` byte layout stability across engine versions is training-knowledge-grade (**UNVERIFIED**); a Godot upgrade is a save-compatibility event for stored bytes and is covered by the golden fixture check.

## Risks
- **`flush` does not imply fsync, so a power cut can lose a "verified" generation.** Mitigation: the ring (at least two verified generations during any swap), T-6, and the bounded loss of one interval; SAVE-WRK-1 c records what the platform does.
- **Antivirus or an indexer holds the target (READ-held is only a proxy).** Mitigation: `RENAME_RETRY_COUNT`/`READ_RETRY_COUNT`, the `.bak` swap, the abandon-and-quarantine rule, and SAVE-WRK-1 a with Defender and OneDrive on.
- **Engine ERROR spam from `bytes_to_var` on hostile or fuzzed bytes (probed) trips gdUnit4 or warnings-as-errors.** Mitigation: decode only after hash checks; the fuzz suite mutates and re-hashes only in a dedicated test configuration that ADR-0010 must allow; recorded as a cross-ADR assumption.
- **A stray object, vector or `StringName` in a snapshot reaches disk.** Mitigation: the walk and the write-side decode (§ 1.2); a unit test per block that feeds a snapshot through encode, decode and walk.
- **Process exit prints a `~Thread` WARNING and an ObjectDB leak report (probed).** Mitigation: ADR-0010 allow-lists them for the quit path; an abandoned worker is the only source.
- **A worker blocked in a syscall rather than a sleep may keep the process alive at exit.** Mitigation: SAVE-WRK-1 d; if it does, Save & Quit reports `FAILED` and the player may force-quit; no data is at risk (the ring is intact).
- **The snapshot frame exceeds 14.9 ms by more than one frame, or on RM-DECK by a visible amount.** Mitigation: the rung ladder of § 1.9; the gate keeps the frame away from tells.
- **Registering fault domain 1 from a module that registers no block is outside ADR-0003's stated examples.** Mitigation: assumption recorded; ADR-0003's registrar already exposes `register_fault_domain` independent of blocks.
- **`min_reader_version` equals `format_version` so no older build ever opens a newer file.** Intentional for the MVP; the field exists so a later additive change can lower it.
- **`block_versions.json` and the live registry drift.** Mitigation: the boot cross-check refuses to start.
- **Typed-container and `PackedByteArray` round-trip beyond the probed cases** (nested typed containers, large arrays) is assumed from the probed behaviour. Mitigation: the per-block encode-decode-walk unit test.
- **Packed arrays, Arrays and Dictionaries are reference-shared across threads, so a retained alias races the worker or changes the data under the writer.** Mitigation: ownership transfer with `.duplicate()` / `.duplicate(true)` for anything the main thread keeps, a worker that never mutates an argument, and the alias unit test (§ 1.6).
- **Rename-over is probably not atomic on Windows.** Mitigation: it is used only for the rebuildable `campaign.json` (accepted exposure); the epoch uses two alternating files with `seq` and CRC; SAVE-WRK-1 b and i measure the window.
- **A window close, Alt+F4 or OS shutdown cuts a write in flight.** Mitigation: `SaveHost` sets `auto_accept_quit = false` and routes the close request to a polled quit flow that never blocks (§ 1.6); a test drives it.
- **`Thread.start` can fail, and a `Thread` freed while running orphans its worker.** Mitigation: the returned `Error` ends the job as `SL_WRITE_WORKER_DIED`; every job stays in `SaveService.jobs` until reaped; a freed live job is a debug fault.
- **A worker that is mid-`store_buffer` or touching freed singletons at exit may misbehave (use after free at exit), UNVERIFIED.** Mitigation: the worker receives pre-globalised paths only and checks `quit_requested` between stages; SAVE-WRK-1 d tests it on dev and release builds.
- **`SaveHost` depends on ADR-0001's `HOST_SERVICE` constant and on the KRN-05 known-node walk.** Mitigation: the constant is named and valued once in ADR-0001 (TD-04); ADR-0010 KRN-03 lists it.

## Performance Implications
- **CPU (main thread)**: Capture is the kernel's (`SNAPSHOT_BUDGET_MS` 16.7 ceiling). Save/Load adds `var_to_bytes` per block (synthetic: 32 blocks / 860 KB in 1.93 ms, dev machine) and a small hand-off, bounded by `SAVE_ENCODE_BUDGET_MS` 4 and `WRITE_HANDOFF_MAX_FRACTION` 0.05 as log thresholds, never truncating. Load adds header parse, `bytes_to_var` (synthetic 3.5 ms for 860 KB) and the type walk (about 5 to 20 ms for a typical save and 10 to 30 ms for a Graph-sized payload, estimate; target at most 4 ms at 30 000 nodes, run on the hot-copy worker when possible). One over-budget frame per autosave is accepted pending SAVE-WRK-1 f (§ 1.9). Release-export numbers on RM-DESKTOP and RM-DECK are **pending the spike**; every figure above is probed 2026-10-28, synthetic.
- **CPU (worker)**: SHA-256 (0.7 ms at 300 KiB, 4.9 ms at 2 MiB, probed), file I/O (2 to 100 ms, AV adds 50 to 500, GDD estimates, UNVERIFIED), re-read and decode. None of it on the main thread.
- **Memory**: Two hot decoded generations (SL-11) at 100 to 300 KiB plus decoded overhead, measured by SAVE-WRK-2; the captured payload and encoded bytes live until hand-off; caps `MAX_SAVE_BYTES` 64 MiB and `MAX_BLOCK_BYTES` 32 MiB bound hostile input.
- **Load Time**: Estimate `restart_ms` 140 to 196 ms against the 1000 ms target (F-8), dominated by the 120 ms black hold; `t_epoch_wait` is one poll frame normally, up to 500 ms on a failing disk, and zero on a carried Continue.
- **Disk**: A typical generation 100 to 300 KiB, three positions plus temporaries, `profile.sav` and quarantine; `SAVE_SIZE_ALARM_BYTES` 2 MiB.
- **Network**: None.

## Validation Criteria
- **SAVE-WRK-1-ACCEPT passes** (gates Accept): a, b, c, d, e, h and i on a Windows `template_release` export (a, b, d with antivirus, OneDrive and a slow disk), g on any Linux build, and f with the synthetic 14-block fixture including the type-walk timing; the results are recorded in the ADR before acceptance. **SAVE-WRK-1-SLICE** (f on the real owner blocks, RM-DESKTOP and RM-DECK) gates the Vertical Slice milestone, not Accept.
- **Fault injection at every T-4 step and every T-6 row** (kill after each step) leaves a recoverable ring: after recovery the newest verified generation is never older than the one before the write started, and no file is lost that was not provably obsolete.
- **Pure pre-check fuzz:** `FUZZ_MUTATION_COUNT` 1000 byte mutations of a golden file never throw, never return a verdict outside the closed `SL_PRECHECK_*` set, never allocate by a corrupt length, and never reach the kernel; a separate re-hashed fuzz configuration (hashes recomputed after mutation) reaches decode and walk and is the only configuration that emits engine `ERROR` lines.
- **Walk tests:** a snapshot containing an `Object` (an `EncodedObjectAsID` after round trip), a `StringName`, a `Vector2i`, a `NaN`, a 17-deep nest and a 250 001-node array each fail `SL_PRECHECK_BLOCK_TYPE_FORBIDDEN` / `_DECODE_FAILED`; at write time the same snapshot ends `SL_WRITE_UNENCODABLE` with all previous generations intact.
- **64-bit tests:** `Hex64` round trip (through Save/Load's header path) over {0, 1, 2^53 - 1, 2^53, 2^53 + 1, 2^63 - 1, 2^63, 2^64 - 1}; uppercase, odd-length, wrong-width and non-hex header strings are refused by the pre-check loop with no engine `ERROR` line; a header JSON number at or above 2^53 is refused; a payload `int` of 2^53 + 7 round-trips through encode, decode and restore (`odometer`, TR-shipbody-007).
- **CRC32 vector and epoch pair:** `SlotEpoch.crc32("123456789")` equals `0xCBF43926`; `SlotEpoch.encode` after `resize(12)` round-trips; a flipped bit in one epoch file is read from the other (no rebuild, no log); with both files invalid the rebuild path logs `SL_EPOCH_FILE_REBUILT`; a kill in the middle of the in-place write of the older file leaves the other file valid and the epoch never lower than the last durable value; `pick` returns the higher `seq`.
- **Epoch tests (AC-SL-142, AC-SL-145):** death advances; Save & Quit then Continue of the newest `QUIT` generation carries and writes nothing; Continue of an `AUTO` generation advances; saturation at 2^32 - 1; a step-back and a deleted manifest never lower it; the same (save bytes, epoch) replays an identical state hash and a different epoch re-keys only threat draws; `request_restore` is never called before `EPOCH_DURABLE` except on the injected 2a path.
- **Thread tests:** a worker killed by an injected GDScript error is reaped as `SL_WRITE_WORKER_DIED` within one poll; an abandoned job's late generation lands in `quarantine/` as `STALE_EPOCH`; no live thread is ever joined (a lint test over the Save/Load module); `MAX_LIVE_ABANDONED_JOBS` is enforced; an injected `Thread.start` failure ends the job as `SL_WRITE_WORKER_DIED` with no `.tmp`; a live job is never dropped from `SaveService.jobs` (freeing one fails in debug). **Alias test:** a buffer is handed off, the retained alias is mutated (append and resize), and the worker output is unchanged; the test fails if the alias is kept without `.duplicate()`.
- **Quit tests:** with an injected stalled worker, Save & Quit returns `FAILED` at `SAVE_QUIT_TIMEOUT_MS` (on a `FakeClock`) and the process exits on request without hanging. **Close-request test:** `NOTIFICATION_WM_CLOSE_REQUEST` with `auto_accept_quit` false routes by kernel state (RUNNING and PAUSED write then call `request_shutdown`, LOADING defers, FAULTED and DOWNED write nothing), never blocks, and `get_tree().quit()` is reached only through `request_shutdown`.
- **Lock test (Windows):** a second process cannot rename a held `campaign.lock` and opens READ_ONLY; a crashed holder leaves no stale lock.
- **Epoch-wait pause test:** a pause requested during the epoch wait of § 3.3 still ends with exactly one `request_restore` reaching `LOADING` (OQ-J).
- **Observation tests:** `pod_arrived_seq` and `berthed_seq` increments are compared with the last-seen values (several events in one catch-up frame are not lost); with the members absent the triggers never fire; a load re-reads the last-seen values and fires no autosave. A lint test confirms `src/save/` has no `Node`, no `_process`, no `Time.*` and no `call_deferred`, and that `created_unix` is never read by ordering.
- **Hitch measurement (OQ-14):** the synthetic 14-block fixture's capture frame P99 (SAVE-WRK-1-ACCEPT f) and, at the Vertical Slice, the real 14-block slice's capture frame P99 on RM-DESKTOP and RM-DECK, release export, with the kernel's uncached capture-time `H64` (SAVE-WRK-1-SLICE); the ADR records whether rung 1 or 2 is needed.
- **Version tests:** a v1 golden loads; a stand-in with a bumped `schema_version` migrates through the owner chain and is not written back; a file whose `registry_epoch` differs and whose mandatory set fails is INCOMPATIBLE-dev and not quarantined; a `catalogue_version` above the build's is `SL_PRECHECK_CATALOGUE_NEWER` and not quarantined; the boot cross-check refuses a retired-but-registered block.
- **Zero-block test:** with Save/Load booted the registry holds exactly the kernel's own `kernel.clock` plus the registered game blocks and no Save/Load block or hook.

- **OQ-G.** `Thread` exit WARNING and the `bytes_to_var` engine `ERROR` lines: ADR-0010 § 8.6 decides how the lint and gdUnit4 configuration tolerate them (a cross-ADR assumption).
